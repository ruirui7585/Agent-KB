# PM Delivery Workflow

## 定位与交付流程（直接输出高保真原型 + PRD）

作为唯一的产品需求与原型交付编排器，将“自动拿到云端聊天思路 → 轻量契约 → 直接生成高保真静态原型 `index.html` → 补全完整 `PRD.md` + 本地预览 →（按需）Vercel 只读部署”串成**无缝自动化闭环**。执行准备检查内置于本 Skill，不调用独立 `contract-review`。

```text
第0步（自动抓云端总结）→ 第1步（提炼轻量契约与白名单）→ 第2步（直接生成/局部更新高保真 index.html）→ 第3步（补全 PRD.md、边界核对与本地预览）→ 第4步（按需 Vercel 只读部署）
```

```text
用户最新明确确认 > Feature Contract > 项目规范 > 已有旧逻辑 > Agent 默认判断
```
- 保留未被废弃的旧逻辑；每个阶段开始只报一句：`当前阶段：[阶段名称]｜预期产出：[一句话]`。

## 执行流程

### 第零步：自动抓取云端模型“收口总结”（免搬运 · 严控 Token）
当用户指出思路在云端模型（ChatGPT / Claude / Gemini / Kimi / DeepSeek / 豆包等）或网页文档中时，按以下顺序只读获取：
1. **浏览器标签页精准截取（首选，只抓最后 1 条收口总结）**：
   - 调用 `chrome-devtools` MCP 的 `list_pages` 查看已打开标签页，按模型名、URL 或标题关键词定位唯一对话标签页（若存在多个候选标签且无法区分，列出标题请用户点选 1 个，不得猜错页面）。
   - 执行 `evaluate_script` 在浏览器端完成裁剪后再回传：**默认只提取最后 1 条 AI 助手完整回复**（即你在云端发“收口”后模型吐出的 1 页总结，匹配如 ChatGPT `[data-message-author-role="assistant"]`、Claude `.font-claude-response`、Gemini `model-response` 的最后一个节点；硬上限 `6,000` 字符）。
   - **禁止无脑拉全量历史或全页 `body.innerText` / `take_snapshot`**：只有当最后 1 条明显不是总结且缺失背景时，才返回“末尾 2 轮对话 + 前序用户提问前 30 字索引”，并按需单点回查指定轮次；仅在脚本受执行策略限制时才降级用 `take_snapshot`。
   - **安全与权限边界**：严格只读，不点击发送、不改动网页状态；遇未登录页、授权拦截或人机验证（CAPTCHA）**立即停止并诚实告知**，绝不绕过任何验证。
2. **桌面端剪贴板兜底**：若用户使用原生桌面客户端，可按需通过 `pbpaste` 读取刚复制的收口总结。

### 第一步：自动提炼轻量契约与防加戏锁（不阻塞推进）
1. **自动收口**：若已有 `~/.kb/templates/feature-contract-template.md` 契约则直接读取；否则从第零步抓回的云端聊天记录或用户口述中，**自动提炼**出轻量 `Feature Contract`（含需求目标、交付范围、**画板白名单**、**Strict Non-Goals** 与 `TBD` 清单），写入需求目录 `README.md` / `FEATURE_CONTRACT.md`。
2. **范围自锁**：未写入白名单的状态、弹窗、统计卡或交互，**严禁画进原型**，仅归入 `TBD` 或后续第 3 步的边界报告。
3. 仅当缺少目标项目/目录或存在无法兼容的致命规则冲突时才暂停；其余情况**不停顿、直接进入第二步**。

### 第二步：直接生成或局部更新高保真静态原型（`index.html`）
- 遵循工作区 `COMMON_UI_RULES.md` 与目标项目 `ui/UI_SYSTEM.md`（涉及英文前台文案时按需调用 `~/.kb/skills/social-ui-copy/SKILL.md`），按白名单**直接生成高保真静态 `index.html`**（拆包外联 `css/style.css` + `js/app.js` + `assets/`，含封面背景卡与左侧折叠目录，严禁超出白名单加戏）。
- 若针对已有原型调整，严格执行 `Patch-Only`（只改被点名画板或局部文件，其余画板原样不动）。

### 第三步：自动补全 `PRD.md`、边界核对与本地预览
- 依据轻量契约与原型结构按 `~/.kb/templates/prd-template.md` **自动补全完整 `PRD.md`**，并复核权限、时序并发、回滚、存量级联、数据口径、极限值及前后台一致性边界（列出 P0/P1 缺口及推荐默认口径）。
- 执行 `COMMON_UI_RULES.md` §3 静态自检（唯一 `index.html` 非空、白名单 0 加戏、`social-ui-copy` 文案合规、外联资源无 404、实测 `getBoundingClientRect()` 宽高锁定、无控制台报错、目录/双语/后台只读边界正常），并在内置浏览器打开本地预览。

### 第四步（按需）：部署 Vercel Production（公网整站只读）与最终同步
本地高保真自检通过且需线上评审时执行：
1. **公网整站只读红线**：公网仅允许浏览、滚动与评审导航（目录/双语），禁用全站一切修改型交互（含仅浏览器临时生效的按钮/表单/输入/上传/拖拽/排序/设置/状态切换）与写入入口；服务端须拒绝未授权写入且禁 URL 参数绕过，内容仅通过修改本地文件并重新执行 `vercel deploy --prod` 更新。
2. **发布命令**：检查无敏感内容，优先用 `vercel`（否则 `npx --yes vercel@latest`，禁全局安装），`vercel whoami` / `vercel link --yes` → `vercel deploy --dry --format=json`（`.vercelignore` 排除 `PRD.md` 等内部文档）→ `vercel deploy --prod --yes`。
3. **匿名实测**：以匿名身份验证页面非空、资源正常、双语无混排、修改型交互不可用、写入接口被拒、与本地一致并核查目标地区访问（未验则诚实标“部分完成”），最终一次性同步交付报告。

## 暂停与禁止事项

- **仅在以下情况暂停**：无法访问或定位云端聊天页（含未登录/人机验证）；目标目录缺失或核心规则致命冲突；存在涉及收费/权限/状态机的 P0 阻塞矛盾；同一修复或部署超 3 轮失败；存在无法排除的敏感数据。
- **禁止**：绕过登录/CAPTCHA；未锁白名单与边界就直接盲目整页重写浪费 Token；越界加戏；生成 `delivery.html`；虚报未执行的验证。
