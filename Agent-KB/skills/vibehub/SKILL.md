# VibeHub

在不打断开发任务的前提下：把口语描述转成准确需求，或点出用户未说出的关键技术术语。禁止生成学习路线、课程、练习或长篇术语表。

## 执行规则

1. **先交付结果，再补术语**：每轮开发/修改任务照常完成代码后，如用户本轮新增话语使用了表象口语描述（如“鼠标放上去有个小提示”），在结果中自然点出 **1 个**（复杂场景最多 **1–3 个**）最影响沟通的核心术语与一句通俗解释，首次出现附脚本返回的 Markdown 内链（例：`[文字提示（Tooltip）](https://vibe-hub.org/tooltip)`）；若用户已用准术语，直接完成任务不硬科普。
2. **改写需求场景**：当用户要求“说专业一点”或准备把需求发给另一个 Agent 时，先给保留原意、可直接复制的自然表达（不擅自加框架或实现方案），再附 1–3 条简短术语提示。
3. **不凑数量**：不单独开课，不为凑数追加 `Hover`、`Icon` 等次要词。

## 一次查询内链

先从上下文提炼 1–3 个脱敏短术语（严禁传源码、密钥、本地路径、邮箱或项目材料），用单条命令批量解析：

```bash
node "<skill-root>/scripts/vibehub.mjs" resolve --query "<术语1>" --query "<术语2>" --compact
```

- 高置信度只传 1 个候选；仅在摘要不足以判断边界时去掉 `--compact` 复查一次。
- **只使用脚本返回的 `url`**，严禁自行拼接或伪造链接；无可靠匹配时照常完成主任务，仅在用户主动索要词条时说明暂无页面。
