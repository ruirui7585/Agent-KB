# Implementation Review

审查 `ui-html-build` 产出的静态产品原型。通过审查仅代表静态原型达标，不代表生产代码或接口已完成；不得因页面能打开即宣布通过，也不得因静态原型无业务点击交互而判定失败。

## 模式分流说明

- **`wireframe-only` 模式（轻量审查）**：**仅检查**第 1～4 维（契约白名单覆盖与 **0 越界加戏**、白名单状态覆盖、旧逻辑保护、黑白线框与固定画布尺寸、技术健康）；**不得**因缺少品牌视觉、双语切换、左侧目录或 `prototype-annotation` 标注层而判定失败。
- **`high-fidelity` / 阶段二完整模式（全量审查）**：按第 1～6 维全量验收（含外联 CSS/JS/资源拆分校验），标注层直接对照 `~/.kb/skills/prototype-annotation/SKILL.md` 验收清单。

---

## 审查维度

1. **契约覆盖与防加戏（Scope Creep 检查）**：
   - Feature Contract 白名单内的每个画板与规则均有对应静态 UI，且未改动未点名区域或旧逻辑；
   - **越界加戏审查**：核对 `Non-Goals`，**不得**出现白名单之外擅自新增的页面、状态板、统计卡、多余按钮或模拟交互；不用文字或标注代替已确认需独立成板的分支。
2. **状态覆盖**：按 Contract 白名单核对已选分支；高保真模式下每个独立状态画板具备对应 `data-state` 状态标注。
3. **视觉与固定画布**：风格/变量/Icon（无 Emoji/空框）符合当前阶段标准（线框为纯黑白灰，高保真贴合项目 `ui/UI_SYSTEM.md` 基线）；逐一实测画布 `getBoundingClientRect()` 宽高与目标设备一致（以项目 `UI_SYSTEM.md` 为准，移动端通用默认 `393 × 852px`），窄屏由外层滚动，画布不缩放。
4. **技术健康**：唯一入口 `index.html`（无 `delivery.html` 或平行 HTML），可打开且非空，无控制台阻断错误、404 或失效绝对路径；`data-page-id`、画板 `id`、`data-annotation-id` 唯一可定位，`data-contract-rule` 可追溯。
5. **封面、目录、双语与后台（高保真完整模式）**：
   - 封面含大/小标题及需求背景卡（未接真实 Agent 时禁用应用）；左侧固定目录直读 DOM（独立于 `annotations.json`），支持折叠且关闭标注后仍可用；
   - 若要求 `bilingual`：顶部中英文切换覆盖全页、无混排且不改锚点/尺寸；
   - 含后台时前后台共用唯一 `index.html`，后台目录/筛选/详情/常驻字段说明可用，建议字段明确标识，未定义权限默认只读。
6. **产品标注层（高保真 `prototype-annotation` 模式）**：
   - 严格对照 `~/.kb/skills/prototype-annotation/SKILL.md` 验收清单核查（单一 Runtime、`annotations.json` 唯一事实源、锚点与附件路径合法、固定右侧主面板、Marker 与浮窗联动、本地写回与公网只读边界），本 Skill 不重复复述其细则。

## 问题分级与自动修复规则

| 严重程度 | 判定范围 | 处理原则 |
|---|---|---|
| **阻塞** | Feature Contract 内部冲突、缺关键业务规则 | 暂停并返回 `pm-delivery-workflow` |
| **P0（必须自动修复）** | **越界加戏（Scope Creep）**、契约漏画或误合并分支、用标注代画板、静态表达缺失、控制台阻断错误、旧逻辑回归、重复 HTML/`delivery.html`、锚点/ID 失效重复、画布尺寸错误或缩放；或高保真模式下缺失封面/左目录/后台字段说明、越权写操作、双语漏翻混排、违反 `prototype-annotation` 任意必填验收项 | **直接局部 Patch 修复**，不逐条打扰；越界多余元素直接删减复原；单问题最多修 3 轮，不重写整页、不删历史文件 |
| **P1（原则上修复）** | 视觉明显偏离、标注内容不准确、图片缺 `alt`、浮窗外部点击关闭小问题 | 局部直接修复 |
| **P2（可记录不修复）** | 轻微样式差异 | 记录在发现问题清单 |

## 输出与禁止事项

```text
审查通过 / 审查通过（有 P2 备注）/ 需修复

修复清单:（已自动修复的问题，含清理的越界加戏项）
阻塞问题:（需要返回 pm-delivery-workflow 的问题）
发现问题:（P2 记录）
未验证项:（诚实披露）
```

**禁止**：放任 AI 擅自加戏通过；在 `wireframe-only` 模式用高保真/双语/标注要求卡住线框交付；页面能打开即宣布通过；只查正常态忽略白名单边界；只记录不修复或修复时重写整页；增写业务动态 JS；生成重复 HTML/`delivery.html`；擅改 Contract 或虚报验证。
