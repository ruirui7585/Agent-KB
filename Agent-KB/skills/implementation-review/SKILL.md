# Implementation Review

审查 `ui-html-build` 产出的静态产品原型。审查通过只代表静态原型通过，不代表生产代码、接口或动态业务已经完成。不得因为页面能打开就宣布通过，也不得因原型没有业务动态交互而判定失败。

## 审查维度

### 1. 契约实现完整性
- Feature Contract 每条规则是否有对应静态 UI，或明确说明不产生 UI
- 是否遗漏页面、状态、弹窗、Toast、空状态、异常状态
- 是否实现了契约外未定义的业务规则
- 标注节点的产品字段是否来自 Contract 而非 AI 臆造

### 2. 静态产品表达
- 核心入口、按钮、字段和操作结果是否清楚可见
- 按钮文案、主次层级、启用和禁用状态是否正确
- 弹窗、Sheet、Toast 是否以独立静态状态完整展示
- 触发条件、判断逻辑和预期结果是否通过页面或标注说明
- 全部页面和状态是否无需业务点击即可查看
- 不要求按钮可点击、弹窗可触发或状态可动态切换

### 3. 状态覆盖
- 先根据 Feature Contract 枚举全部会改变可见内容、按钮、入口或操作能力的角色、权限和状态分支
- 每个产生不同 UI 的分支是否使用独立画板
- 是否用文字说明或产品标注代替了缺失画板
- Feature Contract 要求的正常、空、加载、错误、禁用、成功和失败状态是否可见
- 权限受限状态的 UI 是否正确
- 边界值状态（余额为 0、次数用尽等）是否覆盖
- 每个独立状态画板是否至少有一条状态标注
- `pageState` 是否与 Contract、演示目录和画板标题一致，`state` 是否表达正确状态类型，`visibleWhen` 是否说明显示条件，标注目标是否位于对应 `data-state` 画板内
- 状态标注是否说明该状态下可用与不可用操作，而不是只写状态名称

### 4. 旧逻辑保护
- 未被标记废弃的旧功能是否正常工作
- 旧页面导航、样式、交互是否被波及修改
- 旧数据结构和 mock 数据是否被意外覆盖

### 5. 视觉一致性
- 新增 UI 是否与现有产品风格明显不一致
- 组件、间距、字号、颜色是否复用现有变量
- Icon 是否真实、语义匹配且风格统一
- 标注 marker 是否正确定位、不遮挡内容
- 移动端每个页面和状态是否使用目标设备固定画布；默认 iPhone 16 为 `393 × 852px`
- 是否通过浏览器逐一实测画布宽高，而非只检查 CSS 声明
- 窄屏下是否由外层评审区滚动，画布本身不缩放、不拉伸

### 6. 演示封面与目录
- 是否有明确的原型大标题和概括目标、场景或范围的小标题
- 标题下是否有独立“需求背景”卡片；中文与英文内容是否完整，手动编辑是否只作为本地评审草稿
- 未接真实 Agent 时，需求背景的 Agent 修改是否明确标记为交互演示且禁止应用
- 目录是否按“页面或流程章节 → 用户角色与状态画板”分层
- 每个独立画板是否都有二级目录项，且名称能区分角色和状态
- 每个目录项是否通过原生锚点直接定位唯一画板
- 原型目录是否固定在 HTML 左侧、直接读取页面与画板 DOM，并与 `annotations.json` 完全独立
- 目录是否支持整体折叠、页面子目录折叠；一级页面整块热区是否同时定位并切换子目录
- 顶部中文 / English 切换是否覆盖原型、需求背景、目录和后台评审页，刷新后是否记忆且没有中英混排
- 关闭产品标注后，原型大标题、小标题和演示目录是否仍然保留且可用
- 后台在范围内时，前台与后台是否共用同一 `index.html`，后台目录、列表、筛选、详情和字段说明是否可用
- 后台建议字段是否明确标识，未定义权限时是否保持只读且没有强制修改、撤销、退款等操作

### 7. 技术健康
- 唯一展示入口是否为 `index.html`
- 是否生成了重复展示 HTML 或 `delivery.html`
- `index.html` 是否可以打开且页面非空
- 控制台无 TypeError 或阻断性错误
- 资源路径有效，无 404
- 无失效的绝对路径
- `data-annotation-id` 是否唯一，标注是否可以定位目标元素
- `data-page-id` 和画板 `id` 是否唯一，演示目录是否通过原生锚点定位对应静态画板
- `data-contract-rule` 属性是否填写正确、是否能追溯到 Feature Contract

### 8. 产品标注层
- 是否只接入一套 `prototype-annotation` Runtime
- `annotations.json` 是否为产品标注唯一事实源，`localStorage` 是否只保存显示偏好
- 每条标注的 `pageId` 是否与页面 `data-page-id` 对应
- `ruleId`、`triggerCondition`、`expectedOutcome` 和 `acceptanceCriteria` 是否完整且来自 Contract
- 状态画板对应标注的 `pageState`、`state` 和 `visibleWhen` 是否完整
- 图片附件是否可以加载，是否使用项目相对路径并提供非空 `alt`
- 图片是否只是补充证据，没有代替规则、状态和验收文字
- 公网评审模式是否只展示图片，不出现上传、替换或移除入口
- 右侧标注主面板是否只提供内容/状态标注列表，没有页面目录、页面筛选或原型定位入口
- 所有未停用且目标当前可见的标注是否自动显示 Marker，无需先选择目录或点击“定位”
- 隐藏标注后 Marker、面板、高亮和编辑入口是否全部消失
- 隐藏和恢复是否不改变原型布局、页面目录和产品状态
- 主面板是否固定在 HTML 最右侧、不可拖动或缩放，并使用独立评审空间而不覆盖原型
- 面板打开和隐藏时，移动端固定画板尺寸是否保持完全一致；空间不足是否由外层滚动或换行
- 点击内容或状态 Marker 后，主面板是否切换并展开对应标注，目标高亮和标注浮窗是否同步出现
- 标注浮窗是否位于原型右侧、主面板左侧，且不覆盖任何画板或主面板
- 浮窗内部点击是否保持，外部点击或关闭按钮是否关闭浮窗并清除高亮
- 主面板和浮窗详情是否隐藏 `ruleId`、`contractSection`、`acceptanceCriteria`、`device`、`viewport`，同时 JSON 和编辑表单仍保留这些字段
- 刷新后是否恢复显示状态、当前页面、内容/状态类型和选中项
- 本地编辑模式下，主面板与浮窗手动修改是否复用同一表单和保存接口，编辑、删除和重新绑定是否写回 `annotations.json`，保存失败是否明确提示
- 未接真实 Agent 时，“Agent 修改”是否只显示明确演示、影响字段和待确认状态，应用按钮是否禁用且标注数据不变
- 本地编辑模式是否只在保存接口可用时开放写入能力
- 公网评审模式是否隐藏主面板和浮窗中的新增、编辑、删除和重新绑定，且不发送保存请求
- 是否错误地把 `file://` 页面声明为完整标注入口

原型业务交互可以保持静态。标注层的隐藏和定位必须实际可用；编辑和保存只在本地编辑模式要求可用，公网评审模式不得暴露写入能力。

## 自动修复规则

以下问题直接修复，不询问用户：
- 契约明确但未实现
- 状态缺失
- 不同 UI 的角色、权限或状态分支被合并展示
- 文字说明或产品标注被用于代替缺失画板
- 静态页面缺少入口、结果或状态表达
- 控制台错误
- 资源路径错误
- 旧逻辑被误改
- 标注内容与 Contract 不一致
- 标注锚点缺失、失效或重复
- 演示目录、`data-page-id` 或 `pageId` 映射错误
- 原型大标题、小标题或演示目录缺失
- 演示目录层级错误、遗漏画板或锚点失效
- 左侧原型目录与标注耦合、无法折叠或页面热区不能定位
- 右侧标注主面板错误生成页面目录或页面筛选
- 中英文切换遗漏、混排、丢失记忆或破坏锚点和画板尺寸
- 需求背景、双语手动草稿或 Agent 演示保护缺失
- 前后台未放在同一 HTML、后台字段说明缺失或未确认写权限被擅自开放
- Contract 已明确但状态画板缺少状态标注
- 状态标注与画板、目录、`data-state` 或 Contract 不一致
- 图片路径失效、图片正文写入 Base64 或缺少替代文字
- 公网评审模式仍显示图片写入入口或发送上传请求
- 标注层隐藏、恢复、固定右栏或空间释放失效
- Marker 被目录或类型筛选错误隐藏
- Marker、主面板、目标高亮和标注浮窗联动失效
- 标注浮窗遮挡画板、无法点击外部关闭或点击内部误关闭
- 本地浮窗编辑未复用主面板表单和保存接口
- 公网浮窗仍显示编辑或其他写入入口
- 本地编辑模式的文件保存失效
- 移动端画布尺寸不符或随评审窗口缩放
- 标注正文被错误地仅保存到 `localStorage`
- 公网评审模式仍显示写入控件或发送保存请求
- 当前任务新增的重复展示入口

修复原则：局部修改，不重写页面，不扩大需求范围，不补充业务动态交互。未经授权不得删除历史文件。

## 输出

```
审查通过 / 审查通过（有 P2 备注）/ 需修复

修复清单:（已自动修复的问题）
阻塞问题:（需要返回 pm-delivery-workflow 的问题）
发现问题:（P2 记录）
未验证项:（诚实披露）
```

## 禁止事项

1. 页面能打开就直接宣布完成
2. 只审查正常流程，忽略异常和边界
3. 发现问题只记录不修复
4. 修复时重写整个页面
5. 声称验证了未实际验证的项目
6. 因非阻塞问题暂停流程并要求用户确认
7. 因按钮不可点击或页面没有动态交互而判定失败
8. 为通过审查擅自增加 JavaScript 业务交互
9. 把标注 Runtime 的必要交互误判为业务动态交互并跳过验证
10. 生成新的展示 HTML 或 `delivery.html`
11. 擅自修改 Feature Contract
12. 将文字说明或产品标注视为 Contract UI 分支的实现
13. 将静态原型审查通过表述为生产实现已经完成
