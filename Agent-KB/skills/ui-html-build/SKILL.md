# UI HTML Build

## 定位与事实源

将 Feature Contract 转换为可本地预览和评审的静态 HTML 产品原型（严格保持唯一展示入口 `index.html`，不创建 `wireframe.html`、`prototype-v2.html`、`final.html` 或 `delivery.html` 等平行版本，不修改生产项目代码或接入真实 API）。

```text
读取需求与现有原型 → 阶段一：黑白中保真静态线框图 → 用户确认 → 阶段二：原地升级高保真静态 HTML + 产品标注 → 自检 → implementation-review
```

**事实源优先级**：`用户本轮最新明确确认 > Feature Contract > Agent 执行包 > 项目规范 > 当前有效原型 > 视觉参考 > Agent 默认判断`。不得擅自修改 Feature Contract 或臆造权限、金额、奖励、周期和状态机。

---

## 执行前确认

开始前核对：Contract 规则编号、目标用户与入口流程、页面/状态/权限分支范围、目标终端与画布尺寸（未指定移动端设备时默认 iPhone 16 `393 × 852px` 并记录假设）、视觉来源与可复用素材、唯一原型路径与需保持不变的区域。修改前声明：`任务类型 / 目标原型路径 / 允许修改 / 禁止修改 / 需要保持不变 / 验证方法`。路径/终端不明确、存在多个有效原型或规则冲突时暂停询问。

---

## 公共结构规范（线框与高保真阶段共用）

### 1. 演示封面、需求背景与双语切换
- **封面**：包含明确大标题与概括目标/范围的小标题（即使只有单页也不省略）。
- **需求背景卡片**：位于封面标题下，承载用户问题、场景与目标，支持中/英文内容与本地评审草稿编辑（不影响 Contract）；可提供“Agent 修改”演示入口，未接真实 Agent 时必须明确标记为交互演示并禁用应用按钮。
- **双语切换**：顶部固定提供 `中文 / English` 切换，覆盖封面、需求背景、原型页面、画板说明、按钮、目录和后台评审页（记住偏好，不复制 HTML，不改锚点或画板尺寸，不出现中英混排）；产品标注工具保持自身工作语言。

### 2. 左侧固定原型目录
- 固定在 HTML 左侧，直接读取页面（`data-page-id`）与画板（`id`）DOM，完全独立于 `annotations.json`，关闭产品标注后仍保留可用。
- 按“页面或流程章节（一级）→ 用户角色 · 状态画板（二级）”分层，所有独立画板必须列入二级目录并通过原生锚点直接定位（不隐藏未选画板）。
- 支持整体折叠与页面子目录折叠；一级页面整块热区定位并切换子目录，折叠状态仅存浏览器显示偏好。

### 3. 移动端画布标准
- 每个页面与关键状态使用独立固定画板，`width`、`height`、`min-width`、`flex-basis` 锁定为目标设备尺寸（默认 `393 × 852px`，具体项目如 Laka 以项目规则为准），禁止百分比缩放或 `transform: scale()`；窄屏由外层评审区滚动或换行。
- 页面名称、用户角色、页面状态、对应规则编号（`data-contract-rule`、`data-state`）与进入/交互说明放在画布外，不占用设备内容区。

## 阶段一：黑白中保真静态线框图

确认页面完整性、结构、信息层级、操作位置和关键分支覆盖。

- **视觉规范**：页面背景 `#FFFFFF`、主文字与主按钮 `#111111`（白字）、次按钮白底黑字灰框、辅助文字 `#666666`、边框 `#D9D9D9`、禁用 `#BFBFBF`；系统字体 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Helvetica Neue", Arial, sans-serif`；标题 `20/28px` `600`、区块 `16/24px` `600`、正文按钮 `14/22px`、辅助 `12/18px`、`8px` 网格、操作控件高度 `≥ 44px`；不使用品牌色、渐变、复杂阴影或动效。
- **Icon 与内容**：复用项目图标/本地统一线框 SVG，语义匹配（禁止 Emoji、空方框或“Icon”文字）；使用真实产品文案，不用 `Lorem ipsum`，操作结果用文字标注（触发/条件/结果），不实现业务点击交互。
- **状态裁剪原则**：只为主流程默认态、常见可用/禁用/成功/失败分支及高频改变下一步操作的状态生成独立画板；已被前置控件阻止、瞬时技术态、低频异常或仅改提示文案的状态保留在文档或标注中。**产生不同 UI 的角色/权限/状态分支必须独立成板**，禁止单板混写多角色或用文字/标注代替独立画板。
- **完成确认**：线框阶段不生成完整产品标注。完成后请用户确认 5 项：`1.页面是否完整 2.信息层级是否合理 3.主次操作位置是否正确 4.状态和边界是否遗漏 5.是否进入高保真静态 HTML 阶段`。已确认清单即为高保真基线。

---

## 阶段二：高保真静态 HTML

在同一个 `index.html` 原地升级视觉表现（不改已确认的页面目录、`data-page-id`、核心结构与流程）。

- **视觉定性**：有现有设计系统或已确认视觉参考时称为“高保真原型”，无视觉来源时称为“高完成度概念原型”；使用真实匹配文案、图片、头像和图标，保留静默静态展示与原有未废弃功能，不新增业务点击交互或 Contract 外规则。
- **基础版型参考**：列表页（搜索+筛选+列表+空/加载/错误）、详情页（头部+内容+状态+操作）、表单页（字段组+说明+校验+提交）、弹窗/Sheet（标题+内容+主/次按钮+关闭）、个人/设置页（信息+编辑+权限条件）。
- **前后台统一评审（需求含后台时）**：
  - 前台与运营后台共用同一 `index.html`，通过左侧固定入口切换；后台目录定位列表、筛选、详情和常驻字段说明，不依赖标注数据；进入后台页时隐藏标注 Marker、主面板、浮窗及“显示标注”按钮，返回前台后恢复。
  - 先建立字段契约区分 `Confirmed / Proposed / TBD`：仅 `Confirmed` 字段可作正式筛选/操作控件，建议字段明确标识来源与含义；未定义后台权限时默认只读演示（无修改/撤销/退款等写操作）；双语切换同步覆盖后台。

## 产品标注接入（调用 `prototype-annotation`）

- **`ui-html-build` 负责**：为业务元素添加稳定锚点（小写 kebab-case `data-annotation-id` + `data-contract-rule` + `data-state`）、从 Feature Contract 提取规则与状态标注写入 `annotations.json`。
- **`prototype-annotation` 负责**：统一 Runtime（Marker、固定右侧主面板与浮窗、本地保存），严禁在 `index.html` 重建第二套标注系统。
- **布局兼容**：评审区为固定右侧面板预留独立空间（不使用突破宽度的 `max-content` 布局），确保打开/隐藏面板时移动端画板尺寸完全一致；右侧主面板不生成页面目录或按页面筛选。
- **标注字段**：每条标注包含 `id, pageId, page, category, title, description, rules, target, context, status, createdAt, updatedAt`；`context` 必填 `ruleId, triggerCondition, expectedOutcome, acceptanceCriteria`，独立状态画板必含 `pageState, state, visibleWhen`，按需附 `images`（仅相对路径 + 非空 `alt`，禁 Base64/绝对路径/远程 URL）；禁止编写“这是一个按钮”等无效描述或为填字段编造规则。

## 阶段自检、异常处理与交付门禁

1. **自检必过项**（进入 `implementation-review` 前实际验证并披露未验证项）：
   - `index.html` 唯一且非空（`file://` 仅作基础查看），无控制台阻断错误与本地资源 404；
   - 封面大/小标题、双语需求背景卡（Agent 修改未接入时禁用应用）、顶部中英文切换（覆盖全页面/目录/后台，刷新记忆且无混排、不改锚点或尺寸）及左侧独立可折叠目录全部正常；
   - 用浏览器逐一实测画布 `getBoundingClientRect()`，宽高与目标设备 100% 一致且不随窗口缩放；
   - 所有纳入范围的角色/权限/状态分支均独立成板且有对应状态标注，所有可见锚点自动展示圆形 Marker；
   - 主面板固定最右侧（无目录/定位入口）、点击 Marker 联动主面板与原型右侧浮窗（不遮挡画板，外部点击关闭）、隐藏后空间释放、详情隐藏 `ruleId/contractSection/acceptanceCriteria/device/viewport` 五字段、本地可写与公网只读边界正确。
2. **直接修复 vs 暂停返回**：样式/溢出/尺寸缩放/目录遗漏/双语漏翻/锚点失效/遗漏或误合并分支/标注联动与权限错误 → **直接局部修复**；Contract 内部冲突/缺关键规则/无法确定唯一原型/需改核心结构或删核心旧逻辑/涉及生产代码/同问题修超 3 轮 → **暂停并返回 `pm-delivery-workflow`**。

```text
完成状态 / 目标原型路径 / 唯一展示入口 / 页面和状态 / 产品标注 / 修改文件 / 保持不变 / 实际验证 / 未验证项 / 遗留风险 / 下一步：进入 implementation-review
```

## 禁止事项

1. 跳过线框确认直接做高保真、在线框阶段用品牌色，或生成业务动态交互；
2. 生成平行 HTML 版本或 `delivery.html`，或输出独立 Contract 映射表；
3. 将已纳入评审的不同角色/权限/状态分支合并单板并用文字或标注代替独立画板；
4. 使用 Emoji/空方框/文字代替真实 Icon、修改生产代码、擅改 Contract、编造标注或重造标注 Runtime；
5. 声称完成未实际执行的验证，或未经授权修改知识库文件。
