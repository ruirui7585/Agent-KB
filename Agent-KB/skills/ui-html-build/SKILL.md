# UI HTML Build

## 定位

将 Feature Contract 转换为可本地预览和评审的静态 HTML 产品原型。

固定流程：

```text
读取需求和现有原型
→ 黑白中保真静态线框图
→ 用户确认
→ 高保真静态 HTML
→ 产品标注
→ 本地验证
→ implementation-review
```

只保留一个用户查看入口：

```text
index.html
```

不生成独立线框文件、高保真副本或 `delivery.html`。

---

## 事实源优先级

```text
用户本轮最新明确确认
>
已同步的 Feature Contract
>
Agent 执行包
>
项目规则
>
当前有效原型
>
视觉参考
>
Agent 默认判断
```

不得擅自修改 Feature Contract，也不得自行决定权限、金额、奖励、周期、状态生命周期等关键业务规则。

---

## 执行前确认

开始前确认：

- Feature Contract 及规则编号；
- 目标用户、入口和核心流程；
- 页面、状态、权限和异常范围，以及所有会改变可见内容、按钮、入口或操作能力的角色、权限和状态分支；
- 目标终端、设备基准和画布尺寸；
- 现有设计系统、已确认视觉参考或“无视觉来源”的明确结论；
- 唯一有效的原型路径；
- 需要保持不变的已有内容；
- 可以复用的页面、样式、组件和素材。

修改文件前输出：

```text
任务类型：
目标原型路径：
允许修改：
禁止修改：
需要保持不变：
验证方法：
```

目标路径、目标终端不明确，存在多个有效原型或规则发生冲突时，暂停并请求确认。已明确为移动端但未指定设备尺寸时，默认使用 iPhone 16 的 CSS 逻辑画布 `393 × 852px`，并记录该假设。

---

## 文件规则

- 修改已有原型时，在当前有效版本中增量修改。
- 新建原型时，只在已确认的目标目录创建一套原型。
- 线框图确认后，直接在同一个 `index.html` 中升级为高保真。
- 不创建 `wireframe.html`、`prototype-v2.html`、`final.html` 等平行版本。
- `index.html` 是唯一用户展示入口。
- 可以使用本地 CSS、JavaScript 和 `annotations.json` 作为运行资源，但不得再生成第二个展示 HTML。
- 不修改生产项目的前端、后端、接口或数据库。

# 阶段一：黑白中保真静态线框图

## 目标

快速确认：

- 页面是否完整；
- 页面结构是否正确；
- 信息层级是否合理；
- 核心入口和操作位置是否正确；
- 状态、权限和异常是否覆盖；
- Agent 是否准确理解 Feature Contract。

线框图不是空框草图，也不是动态原型。

---

## 输出方式

在一个 `index.html` 中静态展示全部页面和关键状态。

要求：

- 打开 HTML 后无需点击即可查看全部内容；
- 页面按用户实际流程顺序排列；
- 每个关键状态使用独立画板；
- 弹窗、Sheet 和 Toast 使用静态展开状态展示；
- 不使用业务 Tab、状态切换器或 JavaScript 业务交互；原型目录、语言切换、前后台评审视图和标注 Runtime 属于评审工具交互，可以实现。

## 演示封面与目录

每个交付原型都必须在同一个 `index.html` 中提供演示封面和目录；只有一个页面或状态时也不省略。

- 封面使用一个明确的大标题说明功能或原型名称，并用一个小标题概括目标、场景或交付范围；
- 目录按用户实际流程排列，一级标题为页面或流程章节，二级标题为该页面下的用户角色和关键状态；
- 每个独立画板都必须出现在二级目录中，不得只列页面而遗漏状态；
- 每个页面使用稳定、唯一的 `data-page-id`，每个画板使用稳定、唯一的 `id`；
- 目录项通过原生 HTML 锚点直接定位对应画板，不使用 JavaScript 切换；
- 目录固定在 HTML 左侧并独立读取页面与画板 DOM，不读取 `annotations.json`，不由标注 Runtime 生成；
- 目录支持整体折叠和页面子目录展开/收起；一级页面整块热区同时定位页面并切换子目录，箭头可以单独切换；
- 目录折叠状态可以作为浏览器显示偏好保存，但不得影响页面、画板或标注数据；
- 所有页面和状态保持完整静态展示，不因目录导航而隐藏；
- 线框与高保真阶段沿用同一套目录，只升级视觉表现；
- 演示目录属于原型本身，关闭产品标注后仍然保留。

目录层级：

```text
原型大标题
原型小标题
├── 页面或流程章节
│   ├── 用户角色 · 状态画板
│   └── 用户角色 · 状态画板
└── 页面或流程章节
    └── 用户角色 · 状态画板
```

每个画板标明：

```text
页面名称
用户角色
页面状态
对应规则
进入条件
```

交互结果使用文字说明：

```text
触发：点击“立即赠送”
条件：用户余额不足
结果：展示余额不足 Sheet
```

不实现真实点击。

## 需求背景与双语评审

- 封面在标题下提供独立“需求背景”卡片，承载用户问题、使用场景和产品目标；
- 需求背景支持中文与英文两份内容；手动修改只保存为本地评审草稿，不改变 Feature Contract；
- 可以提供“Agent 修改”自然语言入口；真实 Agent 未接入时必须明确标注为交互演示、禁用应用按钮，不得伪装生成结果；
- HTML 顶部固定提供“中文 / English”切换，覆盖封面、需求背景、原型页面、画板说明、按钮、辅助文字、原型目录和后台评审页；
- 产品标注工具保持自身工作语言，不因原型语言切换而修改 `annotations.json`；
- 语言选择可以作为浏览器显示偏好记忆；切换语言不得复制 HTML、改变锚点、隐藏状态或缩放画板。

---

## 移动端画布标准

- 每个页面和关键状态使用独立固定画布；默认尺寸为 `393 × 852px`。
- 画布的 `width`、`height`、`min-width` 和 `flex-basis` 必须锁定，不得随评审窗口缩放或拉伸。
- 外层评审区负责换行或横向滚动；画布本身不使用百分比宽度、响应式缩放或 `transform: scale()`。
- 页面名称、规则编号等评审说明放在画布外，不占用设备内容区。
- Feature Contract 或项目规则指定其他设备时，以其尺寸为准。

---

## 线框图视觉标准

- 使用黑白中保真风格，不输出只有空框和占位文字的低保真草图。
- 页面背景使用白色 `#FFFFFF`。
- 主文字和主要按钮使用黑色 `#111111`。
- 辅助文字使用 `#666666`。
- 边框使用 `#D9D9D9`。
- 禁用状态使用 `#BFBFBF`。
- 使用系统字体：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text",
"PingFang SC", "Helvetica Neue", Arial, sans-serif
```

- 页面标题使用 `20px/28px`、字重 `600`。
- 区块标题使用 `16px/24px`、字重 `600`。
- 正文和按钮使用 `14px/22px`。
- 辅助说明使用 `12px/18px`。
- 间距使用 `8px` 基础网格。
- 按钮、输入框等操作元素高度不低于 `44px`。
- 主按钮使用黑色背景和白色文字。
- 次按钮使用白色背景、黑色文字和灰色边框。

---

## Icon 标准

页面需要 Icon 时，必须填充与功能语义匹配的真实 Icon。

优先级：

1. 复用当前项目已有图标；
2. 使用当前项目已有图标库；
3. 使用同一风格的本地 SVG 图标。

要求：

- 图标语义与功能一致；
- 同一页面保持相同线宽和风格；
- 默认尺寸保持一致；
- 不使用 Emoji；
- 不使用空方框；
- 不使用“Icon”文字；
- 不使用无关图标代替。

---

## 内容标准

- 使用真实产品语义，不使用 `Lorem ipsum`。
- 按钮必须写明真实操作，例如“立即赠送”“确认提交”。
- 字段必须写明真实名称，例如“当前余额”“礼物数量”。
- 图片或头像可以使用灰色占位区域，但必须保持正确类型、比例和尺寸。
- 按钮、输入框、导航、Tab、弹窗和 Sheet 必须展示完整结构。
- 不加入品牌色、渐变、复杂阴影、插画或动效。
- 不加入 Feature Contract 未确认的产品能力。

---

## 状态标准

只展示会影响产品理解、研发实现或验收的状态，例如：

- 默认；
- 空状态；
- 加载；
- 成功；
- 失败；
- 禁用；
- 权限受限；
- 余额不足；
- 次数用尽；
- 已完成；
- 已过期。

同一页面因角色、权限或状态不同而改变可见内容、按钮、入口、启用状态、空状态或结果状态时，每个分支必须作为独立静态画板展示。一个画板只表达一个明确的角色与状态组合。

不得用以下内容代替独立画板：

- 在一个画板中同时说明多个角色；
- 用文字描述另一个角色会看到什么；
- 用产品标注代替缺失页面或状态。

不得机械生成与当前需求无关的全部通用状态。

---

## 规则追踪

不输出独立的 Contract 到 UI 映射表。

在业务区块中添加：

```html
data-contract-rule="FR-012"
data-state="insufficient-balance"
```

在画板标题处显示对应规则编号。

线框阶段不生成完整产品标注，避免结构调整后产生无效标注。

---

## 线框图完成条件

必须满足：

- 一个 `index.html` 通过已声明的预览方式可以打开；`file://` 只视为基础页面查看，不视为完整标注入口；
- 封面包含明确的原型大标题和小标题，演示目录覆盖全部画板；
- 无需点击即可看到全部页面和状态；
- 页面结构和信息层级清晰；
- 每个移动端画板符合目标设备固定尺寸；
- Icon 已使用匹配的真实图标；
- 使用统一黑白视觉标准；
- 页面和状态可追溯到 Contract 规则；
- 没有业务动态交互；
- 没有高保真品牌视觉；
- 没有创建平行版本。

完成后请用户确认：

```text
1. 页面是否完整
2. 信息层级是否合理
3. 主次操作位置是否正确
4. 状态和边界是否遗漏
5. 是否进入高保真静态 HTML 阶段
```

用户明确确认后再进入下一阶段。

用户确认的页面与状态清单视为高保真阶段基线。高保真阶段不得擅自合并、删除或增加状态；确需改变时返回线框阶段确认。

# 阶段二：高保真静态 HTML

## 目标

在已确认线框图的基础上，将同一个 `index.html` 原地升级为高保真静态产品原型。

不改变已确认的页面范围、信息层级和核心流程。

---

## 构建规则

- 优先复用当前项目的视觉体系、组件和素材。
- 有已确认视觉参考时，遵循参考中的布局和视觉方向。
- 有现有设计系统或已确认视觉参考时，产出称为“高保真原型”；没有视觉来源时，产出称为“高完成度概念原型”，不得声称还原真实产品视觉。
- 使用真实、符合场景的文案、图片、头像和图标。
- 所有关键状态继续以独立静态页面或区块展示。
- 保留已确认的原型页面目录和 `data-page-id`，只升级视觉表现。
- 不增加产品业务点击、跳转或状态切换。
- 不接入真实 API、后端或生产数据。
- 不因追求视觉效果增加 Contract 之外的产品规则。
- 不删除未被明确废弃的已有页面、状态和交互。

页面可使用以下基础结构：

| 类型 | 基础结构 |
|---|---|
| 列表页 | 搜索 + 筛选 + 列表 + 空/加载/错误 |
| 详情页 | 头部信息 + 内容区 + 状态信息 + 操作区 |
| 表单页 | 字段组 + 取值说明 + 校验反馈 + 提交 |
| 弹窗或 Sheet | 标题 + 内容 + 主按钮 + 次按钮 + 关闭 |
| 个人或设置页 | 信息展示 + 编辑入口 + 权限条件 |

复杂页面可以组合使用，不得为了套模板破坏产品结构。

---

## 前后台统一评审（需求包含后台时）

- 前台原型与运营后台必须放在同一个 `index.html`，通过左侧固定入口切换，不创建第二个后台 HTML；
- 前台目录读取前台页面和画板；后台目录只定位后台列表、详情和字段说明，两者都不依赖产品标注；
- 后台页面根据已确认前台能力派生，先建立字段契约并区分 `Confirmed`、`Proposed`、`TBD`；
- 只有已确认字段可以作为正式筛选或操作控件；建议字段必须清楚标识，并在常驻字段说明区解释来源与含义；
- 未定义后台权限时默认生成只读列表、筛选和详情，不增加强制修改用户数据、撤销完成状态、退款或其他写操作；
- 进入后台评审页时隐藏 Marker、标注主面板、浮窗和“显示标注”按钮；返回前台后恢复原标注显示状态；
- 后台使用虚构数据时必须标明只读演示，不得声称连接真实接口、账户、支付或库存；
- 中文 / English 切换同时覆盖后台页面和后台目录。

# 产品标注

## 职责

`ui-html-build` 负责：

- 添加稳定锚点；
- 从 Feature Contract 生成产品标注；
- 生成或更新 `annotations.json`；
- 保证标注和 UI 对应。

`prototype-annotation` 负责：

- 自动显示 Marker；
- 固定右侧主面板和标注浮窗；
- 内容/状态标注列表、手动修改、Agent 修改演示、删除和重新绑定；
- Runtime 和保存能力。

不得重新构建第二套标注系统。

接入 Runtime 时必须保证：

- 原型评审区为固定右侧面板预留独立空间，面板不覆盖原型；
- 页面或画板容器在剩余空间内换行或由外层滚动，不使用会伸入面板区域的无限制 `max-content` 布局；
- 移动端画板继续使用固定目标尺寸，不因面板显示而缩放或拉伸；
- Marker 是否显示不依赖主面板目录筛选或“定位”；
- 右侧标注主面板不生成页面目录、不按页面筛选；页面与画板定位只由左侧原型目录负责；
- 使用 `prototype-annotation` 自带的 Marker、浮窗、本地编辑和公网只读行为，不在 `index.html` 重写同类逻辑。

---

## 锚点规则

业务区块使用：

```html
data-annotation-id="insufficient-balance-sheet"
data-contract-rule="FR-012"
data-state="insufficient-balance"
```

锚点必须：

- 使用小写英文和 kebab-case；
- 表达业务语义；
- 在原型内唯一；
- 不依赖屏幕坐标；
- 不改变页面视觉。

---

## 标注内容

每条标注对应一个用户可感知的：

- 产品能力；
- 交互规则；
- 权限规则；
- 状态变化；
- 异常或边界处理。

当参考图、截图或视觉证据能直接帮助理解规则时，可以为标注附加 `images`。每张图片使用项目相对路径 `src`、非空 `alt` 和可选 `caption`；图片不能代替文字规则，不写入 Base64、本机绝对路径或远程 URL。

标注至少包含：

- `id`
- `pageId`
- `page`
- `category`
- `title`
- `description`
- `rules`
- `target`
- `context`
- `status`
- `createdAt`
- `updatedAt`

`context` 根据适用情况填写：

- `ruleId`
- `contractSection`
- `triggerCondition`
- `judgmentLogic`
- `expectedOutcome`
- `dataSource`
- `valueConstraint`
- `permissionCondition`
- `exceptionBehavior`
- `acceptanceCriteria`
- `ruleVersion`
- `decisionRef`
- `pageState`
- `componentState`
- `state`
- `visibleWhen`

其中必须填写：

- `ruleId`
- `triggerCondition`
- `expectedOutcome`
- `acceptanceCriteria`

每个独立状态画板至少对应一条状态标注。该标注还必须填写：

- `pageState`：与演示目录和画板标题一致；
- `state`：正常、空、加载、错误、禁用、成功、失败、完成或权限状态；
- `visibleWhen`：进入或显示该状态的条件。

已有规则标注包含完整状态信息时直接复用，不重复增加 Marker。Contract 未定义状态条件或操作差异时不得编造。

不适用的字段可以省略，禁止为填满字段编造内容。

禁止使用“这是一个按钮”“这里展示内容”等无产品价值的描述。

# 验证

完成后实际验证：

- `index.html` 可以打开且页面非空；
- 原型大标题、小标题和演示目录清晰可见；
- 所有计划页面和关键状态均已覆盖；
- 所有产生不同 UI 的角色、权限和状态分支均使用独立画板，未以文字或标注代替；
- 页面符合已确认线框结构；
- Icon、图片和素材正确加载；
- 无明显溢出、遮挡和错位；
- 使用浏览器实测每个移动端画布的 `getBoundingClientRect()`；宽高必须与目标设备完全一致，窄屏下也不得缩小；
- 标注锚点唯一且可以定位；
- 每个独立状态画板至少有一条状态标注，状态名称、类型和显示条件来自 Contract，标注目标位于对应 `data-state` 画板内；
- 演示目录按“页面或流程章节 → 用户角色与状态画板”分层，且每个二级目录项都能通过原生锚点定位唯一画板；
- 左侧目录独立于标注数据，覆盖全部页面和画板，支持整体折叠、页面子目录折叠和一级热区定位；
- 顶部中英文切换覆盖全部原型文案和目录，刷新后保持选择，切换前后锚点、状态和画板尺寸不变；
- 需求背景卡片存在，中文与英文内容可手动编辑；未接真实 Agent 时，Agent 修改仅展示明确演示且不能应用；
- 当后台在范围内时，前台与后台共用同一 `index.html`，后台列表、筛选、详情和字段说明可用，未确认字段有明确标识且默认无写权限；
- 标注内容来自 Feature Contract；
- 标注图片附件可以加载、具有替代文字，且只使用项目相对路径；
- 标注层可以隐藏和恢复，关闭后不影响产品页面及演示目录；
- 右侧标注主面板不存在页面目录或页面定位入口；
- 固定右侧面板打开时不覆盖原型，隐藏后释放评审空间，且两种状态下画板尺寸完全一致；
- 当前可见目标的 Marker 自动出现，不要求先选择主面板页面或类型；
- 点击内容或状态 Marker 后，主面板展开对应条目，原型右侧浮窗正确显示且不覆盖画板；
- 浮窗内部点击保持显示，外部点击关闭；本地模式可以在浮窗内编辑，公网模式不显示写入入口；
- 标注详情不展示 `ruleId`、`contractSection`、`acceptanceCriteria`、`device`、`viewport`，但 `annotations.json` 和编辑表单仍保留这些数据；
- 本地标注浮窗区分“Agent 修改 / 手动修改”；未接真实 Agent 时应用按钮禁用且标注数据不变；
- 本地资源无关键 404；
- 控制台无阻断性错误；
- 已有原型中的无关内容未被破坏。

不得声称执行了未实际完成的验证。

无法验证时必须说明未验证内容、原因和人工验证方法。

# 异常处理

以下问题直接修复：

- 明确的样式错误；
- 移动端画布尺寸错误或被响应式缩放；
- 页面溢出或遮挡；
- 左侧原型目录遗漏页面或画板、依赖标注数据、无法折叠或锚点失效；
- 中英文切换遗漏可见文案、改变锚点或导致画板缩放；
- 需求背景或前后台入口缺失；
- 后台建议字段未标识、缺少字段说明或擅自增加写权限；
- Icon 或资源路径错误；
- 锚点缺失或重复；
- Contract 已明确但遗漏的页面或状态；
- Contract 已明确但被合并展示的角色、权限或状态分支；
- 标注与 Contract 不一致；
- 对已有原型造成的局部回归。

以下情况暂停并返回 `pm-delivery-workflow`：

- Feature Contract 内部冲突；
- 缺少关键业务规则；
- 无法确认唯一有效原型；
- 需要改变页面核心结构；
- 需要删除核心旧逻辑；
- 继续执行会修改生产项目；
- 同一问题修复超过三轮。

暂停时输出问题、影响、可选方案、推荐方案和一个需要用户确认的关键决策。

# 完成标准

满足以下条件后进入 `implementation-review`：

- 线框图已经获得用户确认；
- 同一个 `index.html` 已升级为高保真静态原型；
- 页面和关键状态完整；
- 所有产生不同 UI 的角色、权限和状态分支均已独立展示；
- 产品标注和稳定锚点已经生成；
- 原型与 Feature Contract 一致；
- 页面可以本地打开；
- 无阻断性错误；
- 未验证项已经如实记录。

审查按照静态原型标准执行，不得因为页面没有业务动态交互而判定失败。

审查通过后，当前 `index.html` 即为最终展示和交付入口，不再生成 `delivery.html`。

# 禁止事项

1. 跳过线框图直接生成高保真原型。
2. 在线框图阶段使用品牌色和高保真视觉。
3. 在线框图或高保真阶段实现业务动态交互。
4. 创建多个展示 HTML 或平行原型版本。
5. 输出独立 Contract 映射表。
6. 生成重复的 `delivery.html`。
7. 修改生产项目代码或接入真实 API。
8. 擅自修改 Feature Contract。
9. 自行猜测关键业务规则。
10. 使用 Emoji、空方框或文字代替真实 Icon。
11. 编造产品标注内容。
12. 删除未被明确废弃的旧逻辑。
13. 重建已有标注 Runtime。
14. 未实际验证却声称已经通过。
15. 未经用户授权修改知识库或其他 Skill。
16. 将不同角色、权限或状态合并到同一画板并用文字说明差异。
17. 使用产品标注代替 Contract 已明确的页面或状态。
