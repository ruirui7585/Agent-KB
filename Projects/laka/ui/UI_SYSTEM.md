# Laka UI System

> 状态：生效中
> 产品基线：Laka iOS 1.4.7 正式版
> 截图设备：PM 提供的 iPhone 17 Pro
> 主验收视口：440 x 956 CSS px
> 最后确认：2026-11-19

## 1. 文件目的

本文件是所有 Laka UI 任务的全局视觉与设计系统合同，负责定义：

1. 业务真值与视觉真值的最终解释权；
2. 不可偏离的产品气质与固定宫殿主框架；
3. 颜色、字体、间距、层级与全局组件规范；
4. 正式素材、头像与截图使用规则；
5. UI 视觉与状态验收门槛。

> 跨项目通用 UI 保护、英文取词规范与资源相对路径继承工作区 [COMMON_UI_RULES.md](../../../COMMON_UI_RULES.md)；前后台统一 `index.html` 交付结构与后台字段表规范遵循项目 [AGENTS.md](../AGENTS.md) 第 5 节。Laka 英文社交专有名词与 C 端微文案规范见 [COPY_GLOSSARY.md](COPY_GLOSSARY.md)；单页面结构与局部例外写入 `ui/screens/<screen>/SCREEN_SPEC.md`；截图索引见 `ui/references/reference-index.md`；素材清单见 `assets/asset-manifest.md`。

## 2. 不可偏离的产品气质

- **必须具有**：亲密、年轻、娱乐感、关系感（人物、对话、礼物、房间、身份、关系进度为视觉中心，保持成年社交产品的可信度）。
- **不能具有**：低俗或性暗示廉价感；幼稚、玩具化；低成本、一次性活动页质感；严肃婚恋、相亲或婚介感。

## 3. 信息源优先级

### 3.1 业务真值与视觉真值分开判断
业务真值回答“功能、数值、权限和行为是什么”；视觉真值回答“页面如何组织和呈现”。不能用截图中的历史业务数值覆盖当前配置，也不能将纯业务 PRD 默认为页面视觉改版。

- **业务优先级**：1. 当前已确认的需求或 PRD → 2. PM 明确确认的当前产品行为 → 3. Laka iOS 1.4.7 正式版行为 → 4. 历史需求和历史设计。
- **视觉优先级**：1. 当前需求明确确认采用的蓝湖设计 → 2. 同页面、同状态的 Laka iOS 1.4.7 真实产品截图 → 3. 蓝湖中的正式素材、尺寸、颜色和组件细节 → 4. 对应页面的 `SCREEN_SPEC.md` → 5. 本全局文件 → 6. 明确标注为“推断”的临时决定。

只有业务需求、未明确提出视觉改版时，必须继承当前 UI，只做实现业务逻辑所必需的最小视觉调整。

### 3.2 蓝湖使用规则
- 当前蓝湖项目：`Laka 7-9期后`（`https://lanhuapp.com/web/#/item/project/stage?tid=edb6ff63-e81e-4474-aef0-9c0a542f7922&pid=80169c5f-183c-440f-83a5-5e10f1427f60`）
- 不能仅因设计位于第 7、8、9 期就自动认定为当前生效版本；存在多个冲突候选稿时列出分组和页面名请 PM 选择；找不到当前设计时继承正式版产品截图；禁止静默混合多个冲突版本的局部细节。
- 每个导入素材必须记录蓝湖项目、分组、页面名和获取日期。

### 3.3 正式版截图使用规则
- 保留页面结构、信息层级和产品识别度；不继承明显线上缺陷（遮挡、裁切、错误日期、间距失衡、错误文案、重复内容），已知问题在截图索引或页面规范中标注“不继承”。
- **禁止从截图中裁出真实用户照片作为可复用素材**。
- `reference.png` 必须是真实产品截图，不得被蓝湖图或 AI 生成图替换。

## 4. UI 意图确认机制与前后台视觉分工

每个进行中的需求，在实现前必须在该需求的 `README.md` 或 `PRD.md` 中记录 UI 意图卡：

```text
UI Intent Card
- 业务目标：
- 入口和影响页面：
- 用户角色和平台：
- 要改变什么：
- 哪些区域必须保持不变：
- 必须覆盖的状态：
- 当前产品截图 / 蓝湖来源：
- 素材状态：
- 待确认问题 & 确认状态：
```

- **执行边界**：明确且局部的文案、图标、显隐、顺序调整，复述理解后直接执行；新页面、新布局、新主题、商业化流程、角色差异、权限或跨页面行为，须经 PM 确认后再执行。不再向 PM 询问本文件已定义的常规颜色、圆角、间距、字体和按钮样式。
- **前后台视觉分工**（详见 [AGENTS.md](../AGENTS.md) 第 5 节）：
  - **`App 前台` 视图**：使用 Laka 当前真实 UI 基线完成静态高保真展示；
  - **`运营后台` 视图**：使用黑、白、灰静态线框，不套用 App 品牌配色、宫殿主题或装饰素材，重点表达信息架构、字段分组、任务流顺序与同视图常驻字段解释。

## 5. 产品主框架

### 5.1 固定金色宫殿主题
`App 前台` 内的五项产品一级导航（`Home`、`Moment`、`Party`、`Message`、`Mine`）默认固定使用金色宫殿主题：
- 顶部导航区域使用明亮金色宫殿、拱门背景，向白色内容区柔和过渡；
- 底部五项导航使用同一宫殿视觉语言，Tab 使用正式插画素材（禁止替换为普通线性图标）；
- 激活文字使用深梅紫，激活指示使用鲜明紫色；
- **宫殿背景属于品牌位图素材**，严禁用 CSS 渐变、SVG 几何或 AI 图近似重建；缺少正式素材时必须停止并询问。

### 5.2 可独立主题的功能页
以下功能可在正式截图或蓝湖支持下使用独立主题（仍需保持成年社交质感、信息清晰、奖励有表现力）：
`Recharge / Checkout`、`VIP`、`Relationship / CP`、`BD Center`、`Tasks`、`Voice Room`、`Shop / Wealth / Charm / Diamonds Center`。

## 6. 男女端与平台视口

1. **男女端**：全局共用同一套设计语言（BD、Relationship、VIP、全局导航、素材、弹窗、商业化组件和系统状态不因性别改变视觉系统）。仅由业务规则决定推荐对象性别、任务定义与奖励币种、Income/Agency/Chat Center 等专属入口及权限差异。
2. **平台与视口**：
   - iOS 1.4.7 截图为当前视觉基线，**主验收视口为 `440 × 956` CSS px（iPhone 17 Pro）**；
   - 其他常见 iOS/Android 尺寸自然重排，不允许整屏机械缩放；妥善处理安全区、系统状态栏、键盘高度和底部手势区。

## 7. 全局基础规范

### 7.1 颜色角色

| 角色 | 工作值 | 用途 |
| --- | --- | --- |
| 主文字 | `#2D2D32` | 主标题、正文、主要图标 |
| 次文字 | `#8E8E96` | 时间、说明、未激活标签 |
| 禁用 | `#C9C7CF` | 禁用文字和线性图标 |
| 页面底色 | `#F6F6F8` | 中性页面背景 |
| 表面 | `#FFFFFF` | 卡片、列表、弹窗 |
| 分隔线 | `#ECEBF0` | 低干扰分隔 |
| Laka 紫 | `#603CFF` | 激活 Tab、主要操作 |
| 深梅紫 | `#35104F` | 宫殿主题激活文字和深色图标 |
| 关系粉 | `#FF4FAE` | 亲密度、爱心、未读强调 |
| 奖励橙 | `#FF9E2F` | 金币、价格、暖色奖励 |
| 在线薄荷 | `#3FDEC2` | 在线状态 |
| 消息蓝 | `#55BDF4` | 聊天入口、信息型社交操作 |

- 紫色表达交互品牌，粉色表达关系，橙金表达奖励和商业化，薄荷表达在线，蓝色表达沟通；
- 装饰背景上的正文必须保持中性色和足够对比度；无截图或蓝湖依据时，不随意增加装饰渐变。

### 7.2 字体与排版

- 使用平台系统无衬线字体，支持阿拉伯语和 RTL/LTR 混排（文字方向跟随内容，不只跟随应用语言）；
- 字间距不能为负值，字号不随视口宽度缩放；用户名、国旗、徽章和数值不遮挡，数字/日期/ID/货币保持完整视觉分组；
- App 前台英文专有名词与短微文案按 [COPY_GLOSSARY.md](COPY_GLOSSARY.md) 执行（新功能无现有产品对照时优先对标成熟竞品英文 UI），严禁逐字直译或沿用 `ui/references/reference-index.md` 中已标注“不继承”的旧版不自然英文；
- **身份行三段式抗挤压**：列表/麦位/卡片头部采用「左定宽头像（含外扩框占位）→ 中间信息区 `min-width: 0`（超长昵称单行省略，单行最多展示 2~3 个核心徽章，按 `国旗 > VIP > 等级 > 称号` 优先显示，其余折叠）→ 右侧操作/数值 `flex-shrink: 0`（不被挤歪或出界）」；
- **双向文本数字隔离与压力样本**：阿语旁的数字/ID/倒计时/`VIP10` 须使用 `dir="ltr"` / `unicode-bidi: isolate` 隔离；列表/麦位原型至少包含 1 条长阿英混排昵称与大额数字样本（如 `1,250,000`）。

| 角色 | 字号 | 字重 |
| --- | --- | --- |
| 导航标题 | 17-18 | Semibold |
| 一级 Tab / 页面主标题 | 20-22 | Bold |
| 分区标题 | 18-20 | Semibold / Bold |
| 卡片标题 | 16-18 | Semibold |
| 正文 | 15-17 | Regular |
| 元信息 | 12-14 | Regular |
| 徽章 | 11-13 | Medium / Semibold |

### 7.3 间距与尺寸

- 基础网格：`4 px`；页面横向边距：`12-16 px`；卡片内边距：`12-16 px`；关联元素间距：`8-12 px`；分区间距：`16-24 px`；
- 常规控件高度：`44-48 px`；强主按钮高度：`52-56 px`；最小点击区域：`44 × 44 px`；
- 小标签圆角：`8-12 px`（或胶囊）；卡片圆角：`12-16 px`；弹窗和 Bottom Sheet 顶部圆角：`20-28 px`；
- 棋盘、座位、头像格、商品网格、计数器和导航栏必须使用稳定尺寸或宽高比约束，防止动态内容撑坏布局。

### 7.4 层级与阴影

- 主要依靠对比和图片建立层级，不依赖厚重阴影；
- 列表和设置使用分隔线或底色，不做浮卡堆叠；用户卡和商品卡只使用轻边框或浅阴影；
- 禁止在装饰卡片内部再套一层装饰卡片。

## 8. 全局组件

- **头像**：默认圆形（媒体宫格明确要求时用方形），`object-fit: cover` 保护面部焦点；当前 LTR 构图中在线薄荷点位于头像左上；头像框/VIP 框/关系框必须使用正式图片素材，禁止用 CSS 近似。
- **用户卡**：扫描顺序依次为：1.头像和在线状态 → 2.用户名/国旗/认证或关系身份 → 3.性别年龄/等级徽章 → 4.Bio 或状态 → 5.一个明确的主要社交操作。宫殿渐隐区上使用白色表面；房间推荐卡在截图支持时可用粉紫高亮和 Join 操作。
- **Tab 与筛选**：App 内部一级 Tab 使用文字 + 紫色下划线（激活文字深梅紫/中性深色加粗）；筛选 Chip 保持紧凑；同级互斥选项使用 Segmented Control；评审页外层前后台切换使用中性导航。
- **按钮**：每个区域只允许一个视觉最强操作；主要社交操作使用紫/粉紫/蓝/橙金，次操作用中性表面或轻描边，禁用态降低对比但不能像已选中，红色只用于破坏性操作。未达亲密度门槛前，1v1 音视频入口须呈锁定/置灰态（不得与可拨打态混用）。
- **IM 聊天安全区**：免费聊天卡、亲密度进度或音视频解锁提示条须固定在消息流与输入区之间或顶部常驻区，不悬空遮挡最新两条消息；键盘/表情/礼物面板展开时输入区须随之上移。
- **徽章与商业化/荣誉组件**：未读用粉红/红色圆形白字；在线用薄荷圆点/胶囊；奖励与货币数值必须与正式货币图标成组出现。VIP/勋章/靓号/充值档位卡片须互斥区分 `Active/Current`、`Available/Claim`、`Paused/Expired` 与 `Locked`（带差额）；3/4 列权益宫格统一图标容器尺寸与文案 2 行截断，称号/铭牌锁定固定宽高比。
- **Modal、Bottom Sheet 与 Toast**：遮罩压低底层页面，关闭热区 `≥ 44 × 44 px`；Modal 用于短任务/确认/密码输入/奖励，Bottom Sheet 用于浏览/选择/礼物/表情/工具九宫格（黑色 Sheet 仅用于有依据的高对比娱乐目录），`Toast` 用于不阻断当前流程的轻反馈。
- **状态完备性**：按需覆盖默认、Loading、Empty（禁止用假数据掩盖空状态，须含图标占位 + 解释文案 + 下一步引导操作）、Error/Retry、Disabled/Locked、Permission Denied 及长文本/多语言混排。涉及 **SALFA 语音房**需求时按其独立角色权限（房主/房管/麦上/听众）与麦位规则出图，不套用 Laka 1v1 亲密度解锁规则。

## 9. 素材规则

1. **必须使用正式素材（缺失时标记 `missing-official` 并停止询问，严禁生成替代品）**：
   宫殿背景和五项底部导航插画、Laka Logo、Coin/Diamond 货币图标、VIP 标识和品牌权益素材、Relationship/CP 和核心系统徽章。
2. **临时生成素材（`provisional-ai`）**：仅限需求允许的一次性礼物、临时活动或非品牌装饰实验，必须在 `assets/asset-manifest.md` 中标记 `provisional-ai`。
3. **头像**：优先使用蓝湖正式设计头像；缺失时使用成年、MENA 语境合理的写实临时头像并明确标注（避免幼态、性化姿势、名人脸或文化语境错误图库）。
4. **文件管理**：不覆盖已有素材，按产品用途命名，在 `assets/asset-manifest.md` 记录来源与状态，不创建空白 `reference.png`。

## 10. 验收门槛与 Critical Fail

### 10.1 视觉对照（`App 前台`）
在 `440 × 956` 主视口（及一个更窄、一个更宽常见手机视口）下与正式版截图/蓝湖稿并排核对：结构与信息层级一致、关键位置/颜色/字体/间距/圆角一致、正式素材未被近似替代、无重叠/裁切/滚动陷阱、阿语/英语/数字/国旗/徽章正常共存、未改区域完全一致。

### 10.2 Critical Fail（出现任一即直接不通过）
- 伪造或近似生成正式核心品牌素材（宫殿背景、货币、VIP、核心徽章等）；
- 从 `App 前台` 五项产品一级导航移除固定金色宫殿主题；
- 把截图中的真实用户照片裁出作为可复用素材；
- 在冲突的正式设计稿之间静默选择，或混淆业务真值与视觉真值优先级；
- 改动需求未涉及的页面区域，或关键内容重叠、裁切、被遮挡；
- 漏掉角色、权限或锁定状态；
- 同时涉及前后台却拆成不同 HTML 链接、保留空白一级 Tab，或后台字段未经 `PRD.md` 字段表定义确认就进入线框、缺少同视图常驻字段解释。
