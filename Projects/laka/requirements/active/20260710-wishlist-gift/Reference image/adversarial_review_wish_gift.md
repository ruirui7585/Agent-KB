# 1v1 心愿礼物后台 · 对抗性边界审查

> 审查对象：基于飞书 PRD《1v1心愿礼物》（revision 1173）与我们已产出的后台产品逻辑 / 字段定义（三页：面板关联配置 / 主播维度心愿数据 / 礼物维度心愿数据）。
> 方法：对抗性（adversarial）视角 —— 站在异常场景、状态变更、跨系统一致性、口径边界，找出产品逻辑中**未定义或自相矛盾**的边界。
> 结论：当前三页后台是 PRD 的**子集**（按"不扩展特殊礼物/解锁/价格规则"要求裁剪）。因此审查分两层：① 子集内部自洽性缺口；② 子集与完整 PRD 之间的范围对齐风险。

## 二、P0 关键矛盾（必须解决）

### 2.1 基础礼物"进度计数源"与"数据统计源"未分离 → 完成率可 >100%
- **PRD 原文**：基础心愿礼物「通过礼物面板和心愿入口赠送时计入心愿进度」。即基础礼物从**普通礼物面板**赠送也计入该女生的心愿进度。
- **后台逻辑**：字段定义"有效订单"明确「同一个礼物从普通礼物面板赠送，不计入心愿礼物数据」；且"心愿付费用户数 = 该女生的心愿入口成功赠送去重用户数"。
- **矛盾**：进度（progress）接受两种来源，数据（data）只接受心愿入口。于是——
  - 某男生通过**普通面板**送了基础礼物，使女生心愿**目标达成**（计入进度 → 计为"完成"）；
  - 但他不在"心愿付费用户数"（data 不含普通面板）；
  - 结果：**心愿完成人数 > 心愿付费用户数 → 心愿完成率 > 100%**。
- **未考虑的边界**：产品逻辑从未声明"进度计数源 ≠ 数据统计源"，也未对完成率设上限保护。字段定义中"心愿完成率 = 完成人数 ÷ 付费用户数"在数据口径下会自相矛盾。
- **建议**：显式拆分为两套定义——`心愿进度完成`（来源=普通面板+心愿入口）与`心愿数据完成率`（来源=仅心愿入口）；并规定数据完成率上限 100%，进度完成率可独立展示。

### 2.2 "当日清零"的日期归属在多时序下未定义
- **PRD 原文**：「心愿礼物只在当日有效，无论是否完成都会在当日清零」。
- **未考虑的边界**：
  1. **时区**：Laka 中东市场（沙特/阿联酋/埃及），"当日"按 UTC、按用户本地、还是按平台统一时区？直接决定清零时刻与"今日/昨日"筛选边界。
  2. **跨日赠送**：男生 23:59:50 下单，女生 00:00:10 收到（异步结算/网络延迟）→ 计入哪一日？订单时间、支付时间、结算时间、到账时间四者不一。
  3. **清零与在途订单**：当日 23:59 发起、次日结算的订单，若遇清零，进度/数据归属哪天？
  4. **退款跨日**：当日送、次日退款 → 当日"完成人数/消费金币"是否回滚？回滚到哪一日？
- **影响**：日维度汇总卡、日期范围筛选、配置天数累计，全部依赖"当日"的精确定义，当前逻辑空白。

## 三、P1 重要边界（状态变更与级联）

### 3.1 资格/状态变化对进行中心愿的处置
- **签约状态**：PRD「中途成为非签约女生需隐藏心愿礼物入口」。若女生在已有进行中心愿、且已收部分礼物时**掉签**，进行中配置、已收礼物、收入历史如何处置？隐藏入口 ≠ 清空数据，但前端无入口可管理 → 形成"孤儿配置"。
- **收礼资格暂停**：后台有"收礼资格 暂停（红）"状态，但 PRD 未定义暂停期间进行中心愿是否冻结、已收部分是否保留、恢复后是否续算。
- **特殊礼物解锁门槛跌破**：PRD「近7天收礼价值≥n钻石 获得特殊礼物配置资格」。若配置后 7 天价值因退款/冲正跌破 n，已配置的特殊心愿是否被撤销/冻结？无规则。

### 3.2 后台面板操作对主播进行中配置的级联
- 后台「心愿礼物面板关联配置」可 停用 / 移除 / 设有效期。但：
  - **礼物中心下架 + 面板仍启用**（如示例 Love Box）：前端须"从选择面板剔除"，但已配置该礼物的女生进行中心愿怎么办？冻结？提示？无定义。
  - **有效期过期（已失效）**：示例 Golden Car 已失效，若当时有女生正进行该心愿，过期瞬间配置悬空。
  - **批量停用 / 移除**：对"已收到部分有效礼物"的主播配置，是硬切断、软隐藏、还是禁止操作？后台缺少"存在进行中配置时禁止停用/移除"的护栏。
- **建议**：后台面板操作需增加"存在进行中主播配置"的前置校验与级联策略（冻结展示 / 保留历史 / 禁止移除）。

### 3.3 退款/冲正/风控反转的跨维度级联重算
- 当前仅声明"排除测试订单、风控无效订单"，但**未定义反转发生后如何回滚**：
  - 一笔已计入的心愿订单被退款 → 须从 `心愿付费用户数 / 心愿完成人数 / 心愿消费金币 / 主播收益钻石 / 付费礼物收益钻石 / 心愿完成率 / 心愿礼物收入占比` **同时**回滚；
  - 且要在**主播维度（page2）与礼物维度（page3）双表**保持一致；
  - 还要回滚实时进度条与亲密度。
- **未考虑**：重算的触发时机（实时 / 日终批）、幂等、跨日反转归属、以及"部分退款"的口径。

## 四、P1/P2 范围对齐风险（PRD 有、后台三页无）

### 4.1 特殊礼物维度整体缺失
- PRD 将特殊心愿礼物列为核心类型：解锁门槛（近7天收礼价值≥n钻石）、仅特殊池、不进普通面板、专属动画/消息、更高亲密度、**最多同时 1 个**。
- 后台三页完全未覆盖。PRD 备注「特殊礼物在礼物资源配置中上传，但不上架」——说明特殊礼物存在于礼物中心，但**后台无任何关联配置/状态/数据页面**管理其心愿侧的启用、解锁门槛配置、解锁资格统计。
- 这是"按用户要求裁剪"的范围缺口，但对抗性审查必须指出：**完整 PRD 的后台支撑不全**，特殊礼物的"解锁门槛 n""特殊池管理""每礼物专属资产"均无后台落点。

### 4.2 送礼用户（男生）维度数据缺失
- PRD 全流程是"女生配置 + 男生赠送"，目标是"提升付费用户数和收入"。
- 后台仅有 **女生(主播)维度 + 礼物维度**，**无任何男生(送礼方)维度**（如男生侧心愿赠送转化率、未完成原因、客单价）。
- 对抗性视角：没有送礼方分析，无法定位"男生看到心愿但不送"的流失点，与目标直接相悖。属可观测性盲区。

## 五、P2 次要边界（口径与一致性）

### 5.1 分母为 0 与完成率上限
- `心愿礼物收入占比 = 心愿收入 ÷ 总收入`：总收入=0（新女生/新礼物）时除零；需定义展示为 "—" 或 0%。
- `心愿完成率`：付费用户数=0 时，当前示例显示 0%（合理），但结合 2.1 的 >100% 风险需双保护。

### 5.2 价格变动与历史快照
- 数据页"当前金币价格"读取礼物中心实时价；但某礼物曾以 199 上架、后涨到 299，历史心愿订单按 199 消耗。`消费金币`=实际消耗（正确），但"当前金币价格"列与"消费金币"并列易误读。缺**赠送时价格快照**用于审计对账。

### 5.3 亲密度统计回滚
- PRD「关联亲密度统计 / 更高的亲密值统计」。心愿完成/赠送影响亲密度，但退款、删除、配置过期未定义亲密度回滚规则 → 资产可能虚高。

### 5.4 实时并发进度一致性
- PRD「每3s自动轮播、收礼数量进度」。多男生并发赠送同一女生同一礼物时，进度条存在竞态与最终一致性问题；后台"心愿累计进度"未声明一致性模型（实时写 vs 异步聚合）。

### 5.5 命名/角色模型
- PRD 用「女生（收礼）/ 男生（送礼）」；后台用「主播 / 礼物」，且把"女生"译为"主播"。中东市场性别角色语义丢失；男生视角完全无后台映射。建议统一为"收礼方/送礼方"或保留 PRD 角色词。

### 5.6 多地区/多币种
- 筛选含 沙特/阿联酋/埃及，但价格、金币、钻石均按单一币种假设。"礼物价格区间""心愿收益区间"未声明币种与区域定价差异。

## 六、已覆盖且正确（对抗性确认无漏洞）
- ✅ 金币（用户侧）/ 钻石（主播侧）币种严格区分。
- ✅ 数据查询页全字段只读、详情/趋势抽屉无编辑入口。
- ✅ 礼物价格/图标/状态来自礼物中心、后台不可改。
- ✅ 有效订单排除 测试订单、风控无效订单、退款/冲正（口径方向正确，仅缺反转级联，见 3.3）。
- ✅ 礼物中心状态 与 心愿面板状态 分列展示。
- ✅ 均提供日期范围筛选与详情抽屉。

## 七、优先行动建议
1. **先解 P0**：拆分"进度计数源"与"数据统计源"，给完成率加 100% 上限；定义"当日"时区与跨日/异步订单的日期归属规则。
2. **补 P1 级联**：后台面板操作增加"存在进行中配置"护栏；定义资格变化/礼物下架/有效期过期对进行中心愿的处置；定义退款反转的跨双维度回滚。
3. **对齐范围**：与 PRD 确认三页后台是否永久裁剪特殊礼物/解锁/价格规则；若否，补齐特殊礼物后台落点与男生维度数据页。
