# 礼物系统配置优化

## 需求信息

- 需求名称：礼物系统配置优化
- 创建日期：2026-07-20
- 当前版本：v0.6
- 需求类型：平台能力 / 运营后台 / 礼物消费链路
- 关联业务模块：礼物管理、语音房、1v1 私聊、亲密关系、财富等级、VIP、活动运营
- 关联页面：礼物资源配置、礼物面板配置、礼物 Tab 配置、礼物角标配置、礼物玩法配置、礼物说明 Banner 配置、前台公告原型
- UI 基线来源：当前 Lakalaka 管理系统 `礼物面板配置` 页面；Laka iOS 1.4.7 语音房及私聊礼物面板参考
- 当前有效 PRD：`PRD.md`
- 当前有效 HTML：后台 `prototype.html`；前台公告 `announcement-prototype.html`
- 文档状态：Draft
- 产品状态：Proposed
- 最近更新时间：2026-07-21

## 一句话方案

保留现有礼物基础资源库，将面板 Tab、礼物投放、角标、玩法能力和说明 Banner 分开配置；礼物与 Lucky 中奖公告直接在礼物玩法中配置，不建设独立全服公告后台。

## 文档阅读方式

v0.6 已移除独立全服公告后台。礼物玩法仅配置玩法类型、玩法附加条件和角标标签：全服礼物按单次赠送金额判断，幸运礼物按中奖金额判断；角标支持一个礼物多选。

## 当前范围

- 重构礼物面板配置的数据职责和后台操作流程。
- 新增礼物 Tab 配置。
- 新增角标素材库，角标在礼物玩法中作为标签多选引用，同一礼物支持多个角标。
- 新增礼物玩法配置，统一维护玩法类型和玩法附加条件。
- 新增礼物说明 Banner 配置：模板 Banner 修改文本即可生效；定制 Banner 每次需求单独上传完整样式。
- Banner 点击后打开所绑定礼物的详情说明页。
- 不新增独立全服公告配置；非礼物业务公告不在本需求范围内。
- 公告样式、多语言、范围、跳转、队列、频控、有效期和兜底不在后台展示。
- 提供礼物赠送与幸运礼物中奖两种前台全服公告线框及客户端展示逻辑。
- 定义普通、幸运、全服、音乐、CP、Guardian、财富等级等礼物能力及字段。
- 定义语音房和私聊礼物面板的展示、校验、发送及异常规则。
- 定义旧配置迁移、灰度、缓存和回滚要求。
- 提供礼物系统后台黑白线框原型，并使用 Axhub 展示页面目录、业务标注和评审状态。

## 原型预览

- 入口：`prototype.html`
- 类型：桌面后台黑白线框图，验证信息架构、配置流程和业务规则，不代表正式视觉设计。
- Axhub：运行时、标注数据和页面桥接位于 `axhub/`；发布或分享时必须与 `prototype.html` 一起保留。
- 后台页面：礼物 Tab 配置、礼物面板配置、礼物角标配置、礼物玩法配置、礼物说明 Banner 配置。
- 前台原型：`announcement-prototype.html`，独立展示礼物赠送与幸运礼物中奖两种全服公告。
- 交互：左侧导航、列表、新增模板 Banner、新增定制 Banner、保存/发布 Toast，以及 Axhub 页面和状态控制。

## 不在当前范围

- 重建现有礼物基础信息和礼物资源库。
- 修改礼物价格、币种、结算、分成和 Lucky Gift 概率算法。
- 设计新的礼物动画生产工具。
- 直接修改当前线上后台或 App 页面。
- 升级公共语音房或私聊 UI 基线。

## 事实源与限制

- 当前后台已经存在独立的“礼物资源配置”，本需求不得在“礼物面板配置”中重复维护礼物名称、价格、图标、动画等基础信息。
- 当前“礼物面板配置”按单条“场景 + 分组名称 + 礼物资源”记录管理，包含上架、展示时间、大区、角标、礼物类型、排序等字段。
- 当前分组名称实际承担前端 Tab 语义，但使用自由文本录入，缺少独立 Tab 实体、稳定 ID、状态及排序管理。
- 当前角标作为礼物面板记录的人工配置项，容易与实际功能能力不一致。
- 当前方案仍在讨论阶段，PRD 中标注为“待确认”的内容不得视为已确认业务事实。

## 待解决问题

- CP/Friend 礼物在无关系时是禁止赠送，还是允许普通赠送但不增加关系值。
- Guardian 礼物在未建立守护关系时的处理方式。
- 音乐礼物与语音房背景音乐、房主音频和用户静音设置的优先级。
- 模板 Banner 文案字数和阿拉伯语适配规则。
- 定制 Banner 最终尺寸、文件大小及动图支持范围。
- 礼物详情说明是否支持视频，或仅支持图文。
