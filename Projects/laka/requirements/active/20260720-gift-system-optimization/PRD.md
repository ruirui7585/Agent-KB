# 礼物系统配置优化 PRD

> 版本：v0.6  
> 日期：2026-07-21  
> 文档状态：讨论稿  
> 涉及端：运营后台、iOS、Android、服务端

## 一、需求背景

Laka 已有“礼物资源配置”和“礼物面板配置”。礼物名称、价格、图标、动画等基础信息已经可以维护，本次不重复建设。

当前礼物面板配置同时维护分组、上下架、玩法类型、角标和展示周期，职责混杂。新增 Lucky、全服、音乐、CP、Guardian 等玩法后，如果继续在面板投放记录中逐件配置玩法和上传角标，会产生重复配置、能力与展示不一致、修改成本高等问题。

## 二、需求目标

1. 将 Tab、礼物投放、礼物玩法、角标素材和礼物说明 Banner 分开管理。
2. 礼物相关全服公告统一在“礼物玩法配置”中维护，不新增独立“全服公告配置”页面。
3. 全服礼物和幸运礼物通过玩法附加条件配置公告金额门槛。
4. 角标素材统一上传，在礼物玩法中作为标签多选；同一礼物可配置多个角标。
5. 支持模板 Banner 和定制 Banner，点击后查看绑定礼物的详情说明。

## 三、非目标

- 不调整礼物名称、价格、图标、动画、币种、分成和结算。
- 不调整 Lucky Gift 的中奖概率和奖池算法。
- 不建设通用的平台公告运营后台。
- 不在本需求中配置关系、用户等级、活动奖励等非礼物业务公告。
- 不允许运营编辑公告布局、队列、频控、有效期或失败兜底策略。

## 四、后台信息架构

| 后台页面 | 页面职责 |
| --- | --- |
| 礼物资源配置 | 已有页面，维护礼物基础信息 |
| 礼物 Tab 配置 | 管理前端礼物面板的 Tab、场景、大区、周期和排序 |
| 礼物面板配置 | 将已有礼物投放到指定场景和 Tab |
| 礼物角标配置 | 上传和维护可复用角标素材 |
| 礼物玩法配置 | 配置单一玩法、玩法附加条件及多个角标标签 |
| 礼物说明 Banner 配置 | 配置礼物说明入口及详情内容 |

系统不提供独立“全服公告配置”入口。礼物或 Lucky 中奖是否产生公告，由所属礼物玩法直接决定。

## 五、功能需求

### 5.1 礼物 Tab 配置

| 配置项 | 规则 |
| --- | --- |
| Tab 名称 | 必填，支持多语言 |
| 使用场景 | 语音房或私聊 |
| 所属大区 | 至少一个 |
| 展示时间 | 永久或指定开始、结束时间 |
| 默认 Tab | 同一场景和大区只能有一个 |
| 展示排序 | 数字越小越靠前 |
| 无有效礼物时 | 默认隐藏 Tab，可选展示空状态 |
| 状态 | 草稿、启用、停用 |

修改 Tab 名称不影响绑定关系；停用默认 Tab 前必须指定新的默认 Tab。

### 5.2 礼物面板配置

面板配置仅负责“把哪个礼物放到哪个位置”，不再维护礼物基础信息和玩法参数。

| 配置项 | 规则 |
| --- | --- |
| 礼物资源 | 从现有礼物资源中搜索选择 |
| 场景 | 语音房或私聊 |
| 所属 Tab | 选择当前场景下已启用的 Tab |
| 所属大区 | 至少一个 |
| 展示时间 | 永久或指定时间 |
| 展示排序 | 同一场景、Tab、大区内排序 |
| 运营标签 | 可选，如 New、Limited；不等同于玩法角标 |
| 状态 | 上架或下架 |

列表只读展示玩法类型、附加条件和已选角标。修改这些内容时跳转到玩法配置页面。

以下旧字段从面板编辑页删除：分组名称、礼物类型、是否有角标、角标文件、角标时间、角标是否永久，以及礼物价格等资源信息。

### 5.3 礼物角标配置

角标采用“素材库 + 礼物多选引用”，不在每件礼物中重复上传文件。

1. 运营先在角标素材库上传 PNG/WebP，并生成唯一角标编码。
2. 礼物玩法配置读取所有已启用角标，作为标签多选项。
3. 同一礼物可以选择一个、多个或不选择角标。
4. 保存时记录角标编码数组；角标之间不存在玩法自动绑定或覆盖关系。
5. 修改角标素材后，所有引用该编码的礼物同步使用新素材。
6. 停用已被引用的角标前需提示影响礼物数；停用后客户端不再展示该角标，其他已选角标保持不变。

### 5.4 礼物玩法配置

#### 5.4.1 玩法定义

一个礼物只配置一个玩法。当前不支持附加玩法，也不提供音乐附加、连击等组合选项。

| 玩法 | 定义 | 玩法配置项 |
| --- | --- | --- |
| 普通礼物 | 基础消费礼物 | 无附加条件 |
| 幸运礼物 | 参与现有 Lucky Gift 概率玩法 | 中奖金额门槛 |
| 全服礼物 | 满足金额门槛后产生全服公告 | 单次赠送金额门槛 |
| 音乐礼物 | 送礼成功后在指定范围播放绑定音乐 | 音频、播放范围、时长、打断策略 |
| CP 礼物 | 满足关系条件时增加关系互动值 | 关系类型、增加值、失败提示 |
| Guardian 礼物 | 满足守护条件时增加 Guardian 值 | 守护等级、增加值、失败提示 |

角标不再由玩法自动生成，所有玩法均通过“角标选择”多选引用素材库标签。

#### 5.4.2 附加条件

附加条件根据玩法类型联动展示，不单独展示“公告触发事件”。

| 玩法类型 | 后台展示 | 判断口径 |
| --- | --- | --- |
| 全服礼物 | 单次赠送金额 ≥ `N` Coins | 以一次送礼请求最终成功扣除的金币总额判断；达到或超过 N 时产生全服公告 |
| 幸运礼物 | 中奖金额 ≥ `N` Coins | 以 Lucky 系统最终结算的中奖金币判断；达到或超过 N 时产生中奖公告 |
| 其他玩法 | 不展示附加条件 | 不执行以上金额门槛判断 |

`N` 必须为大于或等于 0 的整数。字段为空、格式错误或小于 0 时不允许发布。公告判断不影响送礼或中奖业务结果。

#### 5.4.3 角标选择

1. 角标选择为多选标签控件，数据来自已启用的角标素材库。
2. 同一礼物支持同时选择多个角标，保存值为角标编码数组。
3. 已选角标需在编辑页回显，并支持逐个移除。
4. 前端同时展示多个角标；具体排列样式由客户端统一实现，后台不配置角标位置。
5. 已停用或已删除的角标不出现在可选列表中；历史引用按角标失效规则处理。

#### 5.4.4 关联礼物说明 Banner

1. 礼物玩法配置增加“是否关联 Banner”必填字段，可选“是/否”。
2. 选择“是”后显示“选择 Banner”必填项，数据来源为状态为“启用”的礼物说明 Banner；选择“否”后隐藏 Banner 选择项。
3. 一个礼物最多关联一条 Banner；同一条 Banner 是否允许被多个礼物引用，由 Banner 类型决定，当前模板 Banner 允许复用，定制 Banner 仅允许关联一个礼物。
4. 关联成功后，客户端在该礼物对应的礼物面板说明区域展示 Banner；用户点击后进入该礼物详情说明页。
5. 礼物玩法配置是“礼物—Banner”关联关系的唯一维护入口；礼物说明 Banner 页面只维护 Banner 内容和状态，绑定礼物信息只读展示，避免两处配置产生冲突。
6. 已关联 Banner 被停用或删除后，前端不再展示；礼物玩法配置列表标记“Banner 已失效”，运营需重新选择或改为“否”。

#### 5.4.5 系统固定处理

以下能力不展示在后台，由服务端或客户端统一实现：

| 固定能力 | 产品规则 |
| --- | --- |
| 公告样式 | 客户端按事件类型使用预置的“礼物公告”或“Lucky 大奖公告”组件 |
| 公告文案 | 服务端返回模板键和变量，客户端按接收用户语言渲染 |
| 展示范围 | 固定为事件所属运营大区内的在线用户 |
| 点击行为 | 固定进入事件发生房间；房间失效时点击无跳转或提示房间已结束 |
| 排队与合并 | 服务端按固定代码策略处理，不提供运营字段 |
| 频控 | 服务端按固定代码策略限制用户和全局展示量，不提供运营字段 |
| 有效期 | 服务端为事件写入过期时间，过期公告不再下发 |
| 隐私与风控 | 服务端统一过滤封禁、注销、隐私限制及风控命中事件 |
| 异常兜底 | 模板、变量或房间数据异常时不阻塞交易，记录日志并放弃公告或使用系统默认文案 |

后台不提供以上字段，也不提供预览。前后端通过固定事件协议和 UI 组件版本关联，UI 设计稿由客户端组件实现，不由运营配置生成。

#### 5.4.5 前台全服公告 UI 与交互

##### A. 礼物赠送公告

适用于全服礼物达到“单次赠送金额 ≥ N Coins”条件后的公告。

| UI 区域 | 展示内容 |
| --- | --- |
| 左侧 | 发送人头像 |
| 中部主文案 | `{sender} sent {gift} ×{count} to {receiver}` |
| 中部副文案 | `{room_name} · Tap to join` |
| 右侧 | 礼物缩略图 |
| 类型标识 | GLOBAL 或地球标识，样式由客户端预置 |

##### B. 幸运礼物中奖公告

适用于幸运礼物最终中奖金额达到“中奖金额 ≥ N Coins”条件后的公告。

| UI 区域 | 展示内容 |
| --- | --- |
| 左侧 | 中奖用户头像 |
| 中部主文案 | `{winner} won {win_amount} Coins from {gift}` |
| 中部副文案 | `{room_name} · Tap to join` |
| 右侧 | 奖杯或幸运礼物缩略图 |
| 类型标识 | `{win_multiple}× WIN`；无有效倍数时只展示 WIN |

##### 共同展示规则

1. 公告以横向悬浮 Banner 展示在语音房顶部安全区域，不挤压麦位、聊天区和底部输入区。
2. 同一客户端同一时刻只展示一条公告；后续公告进入本地等待队列。
3. 当前公告默认展示 5 秒；用户点击后立即执行跳转并结束当前展示。
4. 客户端按服务端下发顺序展示，不在客户端重新计算金额门槛或调整业务优先级。
5. 使用 `event_id` 去重；同一账号在同一设备会话内不重复展示同一事件。
6. 收到事件时若 `expire_at` 已过期，则直接丢弃；排队期间过期也不再展示。
7. 头像、礼物缩略图加载失败时使用系统占位图，不能阻塞文案展示。
8. 主文案单行截断；昵称或礼物名称过长时保留金额、数量等核心结果字段。

##### 点击逻辑

1. 点击整条公告，客户端读取事件中的 `room_id`。
2. 用户已在目标房间时不重复进房，可关闭公告或保持当前页面。
3. 用户不在目标房间时，先校验房间是否存在及是否允许进入；校验通过后进入目标房间。
4. 房间已结束、已关闭或用户无权限进入时，不跳转并提示 `Room has ended.` 或对应权限提示。
5. 点击行为上报 `gift_announcement_click`，包含 `event_id`、`event_type`、`room_id` 和跳转结果。

##### 前端处理流程

```text
接收公告事件
→ 校验 event_id、event_type、expire_at 和必需字段
→ 按用户语言解析模板与礼物名称
→ event_id 去重
→ 加入本地展示队列
→ 当前无公告时渲染对应组件
→ 展示曝光埋点
→ 5 秒自动消失或点击后结束
→ 展示下一条未过期公告
```

#### 5.4.6 多语言

1. 服务端发送稳定模板键，例如 `gift_sent_global`、`lucky_jackpot_won`，以及发送人、接收人、礼物名称、数量、金额等变量。
2. 客户端按每位接收用户的 App 语言选择本地文案模板。
3. 礼物名称使用礼物资源中的多语言名称；缺少当前语言时按项目默认语言链路降级。
4. 阿语采用 RTL 排版，但数字、金额、礼物数量和专有名称保持可读顺序。
5. 缺少模板时使用内置英文模板；变量缺失且无法安全渲染时不展示公告并上报异常。

### 5.5 音乐礼物

音乐礼物需配置音频文件、播放范围、最大时长、音量、并发优先级、打断策略和素材失效降级方式。音乐播放失败不能回滚已经成功的送礼交易。

### 5.6 礼物说明 Banner

礼物说明 Banner 位于礼物面板说明区域，点击后打开所绑定礼物的详情说明页。它不由送礼触发，也不承担全服公告。

#### 模板 Banner

客户端预置布局，运营配置绑定礼物、主标题、副标题、按钮文案、详情说明、场景、大区、语言、展示时间、排序和状态。修改文本后即可生效。

#### 定制 Banner

运营为每次需求单独上传完整 PNG/WebP 素材，并配置备用素材、替代文本、绑定礼物、详情说明、投放范围、展示时间、排序和状态。修改图片中文字时需重新上传素材。

Banner 跳转类型固定为“礼物详情说明页”，跳转字段由绑定礼物自动生成 `gift_id`，不允许自由填写外部链接。

## 六、服务端数据要求

### 6.1 礼物玩法新增字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `primary_play_type` | enum | normal、lucky、global、music、cp、guardian |
| `global_min_send_amount` | integer | 全服礼物单次赠送金额门槛，仅 global 必填 |
| `lucky_min_win_amount` | integer | 幸运礼物中奖金额门槛，仅 lucky 必填 |
| `badge_codes` | array&lt;string&gt; | 礼物选择的角标编码数组，允许为空或包含多个编码 |
| `is_banner_linked` | boolean | 是否在礼物面板关联并展示礼物说明 Banner |
| `banner_id` | string / null | 关联的礼物说明 Banner ID；`is_banner_linked=true` 时必填 |

### 6.2 公告事件字段

服务端生成公告时至少包含：`event_id`、`event_type`、`region_code`、`sender_id`、`receiver_id`、`gift_id`、`success_count`、`success_amount`、`room_id`、`template_key`、`template_variables`、`created_at`、`expire_at`。

`expire_at`、频控、队列、合并、风控和兜底策略属于服务端内部字段或代码常量，不在运营后台展示。

## 七、状态与异常

1. 礼物资源失效、Tab 停用或玩法缺少必填参数时，不允许面板投放上架。
2. 全服礼物未填写合法的单次赠送金额、幸运礼物未填写合法的中奖金额时，不允许发布。
3. 非全服、非幸运玩法不展示也不保存对应金额附加条件；玩法类型切换后清空原玩法不适用的条件。
4. 公告服务异常不影响送礼或中奖结果；只记录失败日志并进入监控告警。
5. 房间已经关闭时，未展示的公告丢弃；已展示公告点击后提示房间已结束。
6. 角标素材失效时隐藏角标，不影响礼物展示和赠送。

## 八、数据与埋点

| 事件名 | 触发时机 | 关键属性 |
| --- | --- | --- |
| `gift_send_result` | 送礼完成 | gift_id、success_count、success_amount、result、scene、room_id |
| `gift_announcement_generated` | 服务端成功生成公告事件 | event_id、event_type、gift_id、condition_type、region_code |
| `gift_announcement_dropped` | 公告被频控、过期、风控或异常丢弃 | event_id、drop_reason、event_type |
| `gift_announcement_impression` | 客户端实际展示公告 | event_id、viewer_id、language、room_id |
| `gift_announcement_click` | 用户点击公告 | event_id、viewer_id、target_result |
| `gift_banner_click` | 用户点击说明 Banner | banner_id、gift_id、scene、language |

公告曝光率以 `gift_announcement_generated` 为分母、去重后的 `gift_announcement_impression` 为分子；按 `event_id + viewer_id` 去重。

## 九、迁移方案

1. 将现有分组名称映射为稳定 Tab。
2. 将现有普通、Lucky 礼物类型迁移为玩法配置。
3. 将现有礼物角标素材去重后迁入角标素材库，并把每件礼物当前角标转换为 `badge_codes` 数组。
4. 将现有礼物和 Lucky 相关公告金额门槛分别迁移为 `global_min_send_amount`、`lucky_min_win_amount`。
5. 删除独立全服公告后台入口及相关运营字段，不迁移关系、等级、活动奖励规则。
6. 灰度期间对比旧、新配置返回结果；异常时可切回旧读取逻辑，不能回滚送礼交易数据。

## 十、验收标准

1. 后台不存在独立“全服公告配置”入口。
2. 玩法列表和编辑页不出现赠送门槛、公告触发事件或自动角标字段。
3. 全服礼物展示“单次赠送金额 ≥ N Coins”，幸运礼物展示“中奖金额 ≥ N Coins”。
4. 玩法编辑页可从角标素材库多选标签，同一礼物可保存多个角标。
5. 列表正确回显所有已选角标，不使用玩法默认角标。
6. 后台不出现公告样式、文案、范围、跳转、队列、频控、有效期、隐私风控和兜底字段。
7. 送礼或中奖未成功时不生成公告；成功但未达到金额条件时不生成公告。
8. 公告服务失败不影响送礼扣费、收礼结果和 Lucky 返奖。
9. 模板 Banner 修改文本后生效；定制 Banner 支持单独上传完整素材。
10. App 可按接收用户语言正确展示英文和阿语公告，阿语布局为 RTL。
