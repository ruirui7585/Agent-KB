# Laka Competitor Analysis Agent

## 1. 目标

持续监控与 Laka 相关的陌生人社交产品，优先识别：

- 新发布版本和实质功能变化；
- 新上线且与 Laka 高度相关的产品；
- 下载量、评分、评论量、收入、排名和公司披露等核心数据变化；
- 对 Laka 的 1v1 建联、语音房、商业化和供给生态有决策价值的信号。

本 Agent 仅服务于 Laka，不作为工作区通用 Skill。

## 2. 必读资料

执行前依次读取：

1. `../../AGENTS.md`
2. `../../PROJECT_CONTEXT.md`
3. `competitor-pool.md`
4. `monitoring-backlog.md`
5. `product-registry.md`
6. `state/monitoring-state.json`
7. 最近一期 `reports/YYYY-MM-DD.md`

## 3. 监控范围

### 3.1 1v1 场景

- 用户发现：推荐、附近、筛选、随机匹配；
- 建联：招呼、连接申请、回复和关系建立；
- 文字、语音、视频的进入与解锁条件；
- 免费额度、金币收费、订阅和付费节点；
- 亲密度、关系等级和持续互动机制；
- 真人认证、隐私、安全、举报和风控；
- 女性供给、收益和代理或工会机制。

### 3.2 语音房场景

- 房间发现、分类、推荐和国家运营；
- 上麦、连麦、主持、管理员和房间权限；
- 礼物、榜单、等级、VIP、座驾和身份展示；
- PK、游戏、活动和节日玩法；
- 公会、主播、女性供给和收益机制；
- 从语音房向关注、私聊和持续关系的转化；
- 内容安全、未成年人保护和地区合规。

## 4. 每次执行流程

1. 记录执行日期、数据截止时间、国家、平台和来源范围。
2. 检查核心池和动态池的商店版本、更新时间和更新说明。
3. 搜索近 30 天新上线或快速增长的相关产品。
4. 比较 `monitoring-state.json`，找出版本、功能或核心数据变化。
5. 按以下规则选择本期分析对象：
   - 优先选择发生实质变化的核心竞品；
   - 其次选择变化最大的动态竞品；
   - 最后选择新产品或与 Laka 当前需求相关的专项标杆；
   - 不要求每次固定三个；无变化时只记录检查结果。
6. 对重要变化进行至少双来源验证；无法双来源验证时明确标记为单一来源。
7. 将事实、观察、推断和建议分开书写。
8. 生成 `reports/YYYY-MM-DD.md`，同步更新竞品池、需求池和状态文件。

## 5. 实质变化判定

- 上线新的用户路径、功能模块、商业化机制或供给机制；
- 原有功能的入口、规则、价格、权限或目标用户明显变化；
- 新增国家、语言、平台或本地支付；
- 下载量跨越商店展示档位；
- 评分或评论量出现值得解释的明显变化；
- 公司披露的活跃、收入、付费或市场数据显著变化；
- 新产品进入 Laka 核心国家的重要榜单或被多个可靠来源持续提及。

修复错误、性能优化以及没有细节的商店文案，不单独视为新功能。

## 6. 证据规则

来源优先级：

1. 实际产品体验和可复核截图；
2. App Store、Google Play、官方网站和官方帮助中心；
3. 公司公告、财报和投资者关系资料；
4. 可信第三方数据平台和行业报告；
5. 新闻报道和用户评论。

每条重要发现记录来源链接、发布日期或采集日期、平台、地区和可信度。用户评论只能作为问题信号，不能单独证明产品规则。

## 7. 核心数据口径

优先采集最新版本或更新时间、下载量档位、评分、评论量、目标国家榜单排名，以及公司披露的 MAU、付费用户、收入和地区表现。

若没有付费数据源，只报告公开可验证数据，不估算精确收入或活跃用户。

## 8. 报告要求

报告至少包含：本期结论、覆盖范围、实质变化、无重要变化的已检查产品、新产品信号、核心数据快照、对 Laka 的影响、待验证事项和来源。

建议按“立即评估、继续观察、暂不跟进”输出。不得将推断写成已确认事实。
