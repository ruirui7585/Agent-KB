> 状态：Draft  
> 来源：`input.md`、`pm-analysis.md`、Laka 当前 v0.6 只读需求资料  
> 日期：2026-07-29  
> 范围：运营后台、服务端、iOS、Android  
> 说明：本文为实现导向草案。未确认行为统一标记为 `TBD`，不得作为最终上线规则。

## 1. 背景

Laka 已有“礼物资源配置”和“礼物面板配置”。礼物名称、价格、图标、动画等基础资源由现有礼物资源库维护，本需求不重复建设礼物资源库。

当前“礼物面板配置”同时承载分组、上架、展示时间、大区、角标、礼物类型、排序等职责。其中“分组名称”实际承担前端 Tab 语义，但为自由文本录入，缺少独立 Tab 实体、稳定 ID、状态和排序管理。随着 Lucky、全服、音乐、CP、Guardian、财富等级等礼物能力扩展，继续在面板投放记录中逐件维护玩法和角标，会造成重复配置、展示与能力不一致、修改成本高、缓存和灰度回滚复杂等问题。

v0.6 方向是保留现有礼物资源库，将礼物 Tab、礼物投放、角标素材、礼物玩法和礼物说明 Banner 分层配置；礼物赠送公告和 Lucky 中奖公告保留在礼物玩法配置内，不建设独立全服公告后台。

## 2. 目标

1. 将礼物资源、Tab、投放、角标、玩法、说明 Banner 的数据职责拆清楚，降低运营重复配置和误配置风险。
2. 用稳定 Tab 实体替代自由文本分组，支持场景、大区、展示周期、默认 Tab、排序和状态管理。
3. 礼物面板配置只负责把已有礼物投放到指定场景和 Tab，不维护基础资源和玩法参数。
4. 建立可复用角标素材库，礼物玩法通过角标编码多选引用，同一礼物支持多个角标。
5. 礼物玩法配置维护单一主玩法、玩法附加条件、角标标签和可选 Banner 关联。
6. 礼物和 Lucky 中奖公告由玩法条件触发，公告样式、队列、频控、有效期、隐私风控和兜底策略不暴露给运营后台。
7. 支持模板 Banner 与定制 Banner，点击固定进入绑定礼物详情说明页。
8. 覆盖迁移、灰度、缓存、回滚、埋点、异常状态和验收标准。

## 3. 非目标

- 不重建礼物基础资源库。
- 不调整礼物名称、价格、图标、动画、币种、结算、分成。
- 不调整 Lucky Gift 中奖概率、奖池或算法。
- 不建设通用平台公告后台。
- 不配置关系、用户等级、活动奖励等非礼物业务公告。
- 不允许运营编辑公告样式、文案、范围、跳转、队列、频控、有效期、隐私风控和兜底策略。
- 不直接修改当前线上后台或 App 页面。
- 不定义新的公域内容合规、隐私展示或平台公开规则；相关规则如需上线由业务方另行确认。

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| 礼物资源 | 已有礼物基础资料，包括 `gift_id`、多语言名称、价格、图标、动画等。 |
| 礼物 Tab | 前端礼物面板的分类实体，具有稳定 ID、名称、场景、大区、排序、默认状态和启停状态。 |
| 礼物投放 | 将已有礼物资源放到指定场景、Tab、大区和展示周期中的配置记录。 |
| 角标素材 | 可复用的礼物标签素材，使用唯一 `badge_code` 被玩法配置引用。 |
| 主玩法 | 一个礼物当前唯一生效的玩法类型，如普通、Lucky、全服、音乐、CP、Guardian、财富等级。 |
| 附加条件 | 随玩法类型联动的配置字段，如全服礼物单次赠送金额门槛、Lucky 中奖金额门槛。 |
| 礼物说明 Banner | 礼物面板内的说明入口，点击进入绑定礼物详情说明页，不由送礼触发。 |
| 礼物公告 | 送礼成功且达到全服礼物条件后生成的前台公告。 |
| Lucky 中奖公告 | Lucky 礼物中奖成功且达到中奖金额门槛后生成的前台公告。 |
| 运营大区 | 后台配置和公告下发使用的区域维度；具体区域枚举以现有 Laka 后台为准。 |

## 7. 端到端流程

### 7.1 运营配置发布流程

```text
确认已有礼物资源
→ 创建或维护礼物 Tab
→ 将礼物投放到指定场景、Tab、大区和展示周期
→ 上传或维护可复用角标素材
→ 为礼物配置单一主玩法
→ 根据玩法填写附加条件
→ 多选角标标签
→ 可选关联礼物说明 Banner
→ 校验配置完整性
→ 发布配置
→ 刷新缓存或等待配置版本生效
→ 灰度观察数据与异常
```

### 7.2 前台公告流程

```text
送礼或 Lucky 中奖成功
→ 服务端判断是否达到玩法金额门槛
→ 生成公告事件
→ 下发给目标范围内在线用户
→ 客户端校验 event_id、event_type、expire_at 和必需字段
→ 客户端按本地语言渲染预置公告组件
→ 展示曝光埋点
→ 用户点击公告
→ 校验并进入事件房间，或提示房间已结束/无权限
```

目标范围当前按“事件所属运营大区内在线用户”处理；是否等同全服范围、是否跨国家或跨语言下发为 `TBD`。

## 8. 功能需求与验收标准

### 8.1 礼物 Tab 配置

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-TAB-01 | P0 | 支持创建和编辑 Tab，字段包括 Tab ID、Tab 名称、多语言名称、使用场景、所属大区、展示时间、默认 Tab、展示排序、无礼物时策略、状态、备注。 | 创建后生成稳定 Tab ID；修改名称不影响已绑定投放；必填缺失不可发布。 |
| FR-TAB-02 | P0 | 同一场景和大区只能有一个默认 Tab。 | 设置新默认 Tab 时系统校验冲突；停用默认 Tab 前必须指定新的默认 Tab，或阻止停用。 |
| FR-TAB-03 | P0 | Tab 状态支持草稿、启用、停用。 | 草稿不下发客户端；启用且在展示时间内才可被投放引用；停用后前端不展示。 |
| FR-TAB-04 | P1 | 无有效礼物时支持隐藏 Tab 或展示空状态。 | 默认隐藏 Tab；选择空状态时客户端展示空文案，具体文案 `TBD`。 |
| FR-TAB-05 | P0 | Tab 列表支持按场景、大区、状态、Tab 名称筛选。 | 筛选条件生效；列表展示有效礼物数和异常状态。 |

### 8.2 礼物面板配置

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-PLC-01 | P0 | 面板配置只负责礼物投放，字段包括礼物资源、场景、所属 Tab、所属大区、展示时间、展示排序、运营标签、状态。 | 编辑页不出现礼物名称、价格、图标、动画等资源编辑字段。 |
| FR-PLC-02 | P0 | 删除旧面板编辑职责：分组名称、礼物类型、是否有角标、角标文件、角标时间、角标是否永久、玩法参数。 | 面板编辑页无法编辑这些字段；列表只读展示玩法、附加条件和角标。 |
| FR-PLC-03 | P0 | 只有启用状态且场景匹配的 Tab 可被选择。 | 停用、过期或场景不匹配 Tab 不出现在可选项；历史已绑定异常需标红提示。 |
| FR-PLC-04 | P0 | 投放上架前校验礼物资源、Tab、展示时间、大区和玩法完整性。 | 任一必需条件无效时不允许上架，并展示可操作错误原因。 |
| FR-PLC-05 | P1 | 支持批量上架、下架、调整展示时间、刷新缓存。 | 批量操作前展示影响数量；部分失败时返回失败项和原因；重复点击不产生重复任务。 |

### 8.3 礼物角标配置

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-BADGE-01 | P0 | 支持角标素材库，字段包括角标 ID、角标名称、`badge_code`、角标类型、素材文件、预览、引用礼物数、状态、备注。 | `badge_code` 唯一；创建后是否允许修改 `TBD`，发布版需固定。 |
| FR-BADGE-02 | P0 | 角标支持 PNG/WebP 上传，并作为礼物玩法多选标签来源。 | 已启用角标出现在玩法多选项；同一礼物可保存多个 `badge_code`。 |
| FR-BADGE-03 | P0 | 修改角标素材后，所有引用该编码的礼物同步使用新素材。 | 客户端刷新配置后展示新素材；旧素材缓存清理策略 `TBD`。 |
| FR-BADGE-04 | P0 | 停用已被引用角标前提示影响礼物数。 | 停用后客户端不再展示该角标，其他已选角标不受影响。 |
| FR-BADGE-05 | P1 | 已删除或失效角标的历史引用处理。 | 可选列表不展示失效角标；历史回显、强制解绑或只读展示规则 `TBD`。 |

### 8.4 礼物玩法配置

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-PLAY-01 | P0 | 一个礼物只配置一个主玩法，当前不支持组合玩法。 | 同一 `gift_id` 只能有一条生效玩法配置；尝试创建第二条时阻止并提示。 |
| FR-PLAY-02 | P0 | 玩法类型包括普通、幸运、全服、音乐、CP、Guardian、财富等级。 | 玩法枚举与前后端协议一致；财富等级具体字段 `TBD`。 |
| FR-PLAY-03 | P0 | 全服礼物显示并校验“单次赠送金额 ≥ N Coins”。 | `N` 必填，必须为大于或等于 0 的整数；达到或超过 N 才生成礼物公告。 |
| FR-PLAY-04 | P0 | 幸运礼物显示并校验“中奖金额 ≥ N Coins”。 | `N` 必填，必须为大于或等于 0 的整数；达到或超过 N 才生成 Lucky 中奖公告。 |
| FR-PLAY-05 | P0 | 普通、音乐、CP、Guardian、财富等级玩法不展示全服或 Lucky 金额门槛。 | 切换玩法后不适用字段不保存；旧字段清空是否可恢复 `TBD`。 |
| FR-PLAY-06 | P0 | 角标选择为多选控件，数据来自已启用角标素材库。 | 保存值为 `badge_codes` 数组；列表和编辑页完整回显多个角标。 |
| FR-PLAY-07 | P0 | 角标不自动启用玩法，玩法也不自动生成角标。 | 选择 Lucky 玩法但不选 Lucky 角标时允许保存与否 `TBD`；若允许，需提示能力与展示分离。 |
| FR-PLAY-08 | P1 | 可选关联礼物说明 Banner。 | 选择“是”时必须选择启用 Banner；选择“否”时客户端不展示说明 Banner。 |
| FR-PLAY-09 | P0 | 公告样式、文案、范围、跳转、队列、频控、有效期、隐私风控和兜底策略不在后台展示。 | 后台无这些字段；公告由服务端和客户端固定策略实现。 |

### 8.5 玩法专项规则

| 玩法 | 已确认要求 | 未确认项 |
| --- | --- | --- |
| 普通礼物 | 无附加条件，按现有送礼链路执行。 | 无。 |
| 幸运礼物 | 接入现有 Lucky Gift 概率玩法；按最终中奖金额门槛判断公告。 | 中奖金额口径是否扣除失败、退款、补偿为 `TBD`。 |
| 全服礼物 | 按一次送礼请求最终成功扣除的金币总额判断公告。 | “全服”范围是否仅运营大区、是否跨国家/语言为 `TBD`。 |
| 音乐礼物 | 送礼成功后播放绑定音乐；音乐失败不回滚送礼交易。 | 播放范围、音量、并发优先级、打断策略、静音策略、背景音乐优先级为 `TBD`。 |
| CP/Friend 礼物 | 满足关系条件时增加关系互动值。 | 无关系时禁止赠送，还是允许普通赠送但不增加关系值为 `TBD`。 |
| Guardian 礼物 | 满足守护条件时增加 Guardian 值。 | 未建立守护关系时禁止、降级普通礼物、还是提示建立关系后再赠送为 `TBD`。 |
| 财富等级礼物 | 可作为玩法类型候选。 | 仅展示等级门槛，还是涉及消费后等级经验增长为 `TBD`。 |

### 8.6 礼物说明 Banner

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-BAN-01 | P1 | Banner 类型支持模板 Banner 和定制 Banner。 | 列表可按类型、场景、状态、Banner/礼物名称筛选。 |
| FR-BAN-02 | P1 | 模板 Banner 使用客户端预置布局，运营配置主标题、副标题、按钮文案、详情说明、场景、大区、语言、展示时间、排序、状态。 | 修改文本后通过配置生效；模板样式不由运营编辑。 |
| FR-BAN-03 | P1 | 定制 Banner 需上传完整 PNG/WebP 素材、备用素材、替代文本、详情说明、投放范围、展示时间、排序、状态。 | 修改图片中文字需重新上传素材；最终尺寸、文件大小、动图支持 `TBD`。 |
| FR-BAN-04 | P0 | Banner 点击固定进入绑定礼物详情说明页。 | 跳转类型不可自由填写外部链接；跳转目标由 `gift_id` 自动生成。 |
| FR-BAN-05 | P0 | 礼物玩法配置是礼物与 Banner 关联关系的唯一维护入口。 | Banner 页面只读展示绑定礼物；不能在 Banner 页面修改绑定关系。 |

| FR-BAN-07 | P1 | 礼物详情说明页承载 Banner 点击后的说明内容。 | 是否支持视频，或仅支持图文为 `TBD`。 |

### 8.7 前台公告

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-ANN-01 | P0 | 送礼或中奖未成功时不生成公告；成功但未达到金额条件时不生成公告。 | 服务端不发送公告事件，并记录判断结果用于排查。 |
| FR-ANN-02 | P0 | 公告服务异常不影响送礼扣费、收礼结果和 Lucky 返奖。 | 交易成功后公告失败只记录日志和告警，不回滚交易。 |

## 12. 埋点与指标

| 事件名 | 触发时机 | 属性 | 用户范围 | 分子 | 分母 |
| --- | --- | --- | --- | --- | --- |
| `gift_config_publish_attempt` | 后台点击发布配置时 | `operator_id`、`config_type`、`config_id`、`scene`、`region_codes`、`config_version` | 后台操作人 | 发起发布次数 | 后台配置编辑次数 |
| `gift_config_publish_result` | 发布成功或失败时 | `operator_id`、`config_type`、`config_id`、`result`、`fail_reason`、`config_version` | 后台操作人 | 成功发布配置数 | 发起发布配置数 |
| `gift_config_validation_failed` | 发布前校验失败时 | `config_type`、`config_id`、`field_name`、`error_code`、`scene`、`region_codes` | 后台操作人 | 被校验拦截的无效配置数 | 发起发布配置数 |
| `gift_panel_load_result` | 客户端打开礼物面板完成加载时 | `viewer_id`、`scene`、`region_code`、`platform`、`config_version`、`result`、`fail_reason` | 打开礼物面板用户 | 成功加载会话数 | 打开礼物面板会话数 |
| `gift_send_result` | 送礼完成时 | `sender_id`、`receiver_id`、`gift_id`、`scene`、`room_id`、`success_count`、`success_amount`、`result`、`fail_reason` | 送礼用户 | 成功送礼请求数 | 发起送礼请求数 |
| `gift_announcement_generated` | 服务端成功生成公告事件时 | `event_id`、`event_type`、`gift_id`、`condition_type`、`threshold_amount`、`actual_amount`、`region_code`、`room_id` | 系统事件 | 生成公告事件数 | 达到门槛的成功送礼或中奖事件数 |
| `gift_announcement_dropped` | 公告被频控、过期、风控或异常丢弃时 | `event_id`、`event_type`、`drop_reason`、`region_code`、`room_id` | 系统事件/接收用户 | 丢弃公告数 | 生成公告事件数 |
| `gift_announcement_impression` | 客户端实际展示公告时 | `event_id`、`viewer_id`、`event_type`、`language`、`room_id`、`platform`、`config_version` | 公告接收用户 | 去重曝光数 | 生成公告事件数 |
| `gift_announcement_click` | 用户点击公告时 | `event_id`、`viewer_id`、`event_type`、`room_id`、`target_result`、`fail_reason` | 公告接收用户 | 去重点击数 | 去重曝光数 |
| `gift_banner_impression` | 礼物面板展示说明 Banner 时 | `viewer_id`、`banner_id`、`gift_id`、`scene`、`language`、`platform` | 打开礼物面板用户 | Banner 曝光数 | 礼物面板成功加载会话数 |
| `gift_banner_click` | 用户点击说明 Banner 时 | `viewer_id`、`banner_id`、`gift_id`、`scene`、`language`、`target_result` | Banner 曝光用户 | Banner 点击数 | Banner 曝光数 |
| `gift_config_cache_refresh_result` | 缓存刷新完成时 | `operator_id`、`config_version`、`result`、`fail_reason`、`affected_regions` | 后台操作人/系统 | 成功刷新次数 | 发起刷新次数 |

口径要求：

- 公告曝光按 `event_id + viewer_id` 去重。
- 公告点击按 `event_id + viewer_id` 去重。
- 配置发布成功率 = `gift_config_publish_result(result=success)` / `gift_config_publish_attempt`。
- 礼物面板有效展示率 = `gift_panel_load_result(result=success)` / 礼物面板打开会话数。
- Banner 点击率 = `gift_banner_click` / `gift_banner_impression`。
- 去重时间窗、跨设备去重和服务端/客户端事件归因规则为 `TBD`。

## 13. 兼容、迁移、灰度、回滚

### 13.1 兼容

- 新配置必须继续引用现有礼物资源库，不复制或改写资源字段。
- 旧客户端读取旧面板配置还是读取兼容聚合接口为 `TBD`。
- 新客户端应基于 `config_version` 拉取 Tab、投放、玩法、角标和 Banner 聚合结果。
- 客户端缺少新字段时应隐藏附加展示，不影响基础送礼能力。

### 13.2 迁移

1. 将现有分组名称映射为稳定 Tab。
2. 将现有普通、Lucky 礼物类型迁移为玩法配置。
3. 将现有礼物角标素材去重后迁入角标素材库，并把每件礼物当前角标转换为 `badge_codes` 数组。
4. 将现有礼物和 Lucky 相关公告金额门槛分别迁移为 `global_min_send_amount`、`lucky_min_win_amount`。
5. 不迁移关系、等级、活动奖励等非礼物公告规则。
6. 旧分组同名、错别字、多语言分组、重复角标编码、失效素材的处理规则为 `TBD`，不得自动合并为确认规则。

### 13.3 灰度

- 支持按平台、版本、大区、用户比例灰度读取新配置。
- 灰度期间需对比新旧配置返回结果，包括 Tab 数量、投放礼物数、排序、角标、玩法、Banner。
- 可接受差异阈值、报警规则和负责人为 `TBD`。
- 配置发布后是自动刷新缓存、运营手动刷新，还是客户端按版本拉取为 `TBD`。

### 13.4 回滚

- 异常时允许回切旧配置读取逻辑或上一版配置版本。
- 不能回滚已完成送礼交易、扣费、收礼结果和 Lucky 返奖。
- 回滚粒度支持全局、大区、场景、配置类型或单配置项为 `TBD`。
- 回滚后需保留操作日志、配置版本和异常原因。

## 14. 依赖

- 现有礼物资源配置数据完整性，包括礼物 ID、多语言名称、价格、图标、动画。
- 现有礼物面板配置、分组名称、角标、礼物类型和公告门槛历史数据。
- 服务端礼物交易、Lucky 结算、公告事件生成、风控过滤、缓存和配置版本能力。
- iOS/Android 礼物面板、语音房公告、私聊礼物面板、RTL/多语言渲染能力。

## 15. 风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 旧分组迁移为 Tab 映射不完整 | 礼物展示位置变化或投放丢失 | 迁移前导出差异清单，人工确认异常映射。 |

| 隐私/封禁用户出现在公告中 | 用户信任和合规风险 | 替代头像昵称和过滤规则为 `TBD`，不可默认上线。 |

## 16. 假设

- 本文默认 v0.6 PRD 中未标注待确认的内容可作为讨论稿基础事实，但仍不是最终上线规则。
- “一个礼物只配置一个主玩法”是当前 v0.6 方向。
- 公告只覆盖礼物赠送和 Lucky 中奖两类事件，不扩展到非礼物业务。
- 配置改造优先保证交易链路稳定，公告、音乐、Banner 等附加能力失败不应回滚已成功交易。
- App 前台 UI 文案默认英文，并支持阿语 RTL；后台运营标签可使用中文。

## 18. 总体验收标准

1. 后台不存在独立“全服公告配置”入口。
2. 礼物资源配置继续作为礼物基础信息来源，面板配置不重复维护资源字段。
3. 礼物 Tab 配置替代自由文本分组，并具备稳定 ID、状态、排序和默认 Tab 管理。
4. 礼物面板配置只负责投放，玩法、角标、Banner 只读展示或跳转维护。
5. 礼物角标通过素材库统一维护，礼物玩法支持多选角标。
6. 一个礼物仅有一个生效主玩法；全服礼物与 Lucky 礼物展示各自金额门槛。
7. 公告样式、文案、范围、跳转、队列、频控、有效期、隐私风控和兜底字段不出现在后台。
8. 送礼或中奖失败不生成公告；成功但未达到门槛不生成公告。
9. 公告服务失败不影响送礼扣费、收礼结果和 Lucky 返奖。
10. 模板 Banner 修改文本后生效；定制 Banner 支持上传完整素材；Banner 点击进入绑定礼物详情说明页。
11. 客户端按接收用户语言展示公告，阿语 RTL 下数字、金额、数量和专有名称可读。
12. 迁移、灰度、缓存、回滚方案覆盖新旧配置对比，且不回滚已完成交易数据。
13. 所有未确认业务行为在本文中保持 `TBD`，不得被实现为默认上线规则。
