## ② 六项检查怎么对到 Dify

1. **分块策略** — 看分段模式：如果文档有明确标题层级（如 PRD 的「功能定义/流程/规则」），建议改用**父子分段**（子段检索、父段给上下文），而不是通用分段定长硬切。通用分段只认 `\n\n` + 最大长度，会切断表格和句子。
2. **上下文断裂** — Dify 原生没有 Contextual Retrieval（不给每块自动补上下文说明）。替代方案：父子分段（子块命中后带出整个父段）是成本最低的补法；进阶做法是在上传前预处理，给每个分段头部加一行「所属章节：xxx」。
3. **检索质量** — 用知识库页面的**「召回测试」**：把 10 个真实问题逐个输入，记录命中的文档/分段和 score。混合检索（向量+全文）+ Rerank 通常明显优于纯向量；Top-K 建议从 3 试到 5-8，配合 Rerank 取前 3。
4. **拼装预算** — Dify 没有 token 预算控制，进 prompt 的内容 = Top-K 个分段全文。检查两处：Top-K 是否过大、单段是否过长（500 tokens × 8 = 4000 tokens 全塞进去）。兜底手段是开 Score 阈值（建议 0.5 起）过滤低相关块。
5. **引用一致性** — 打开「引用与归属」后，回答下方会标来源段落。抽 3 个回答人工核对：引用的分段是不是真的支撑了那句话；若模型说了引用里没有的内容，就是幻觉信号（常见原因：Top-K 太大、低分块混入）。
6. **更新链路** — 本地上传的文档**不会自动同步**，源文件改了必须手动「重新上传/重新分段」，旧分段才会被替换（整文档重索引，不是增量）。Notion/网页同步源可开自动同步。没有「只删某个失效分段」的机制，只能整文档重建——所以文档尽量按主题拆小。

## ④ 改动前先估成本（红线）

- 换 Embedding 模型或改分段参数 = **所有文档重新高质量索引**。估算：知识库总 tokens × 新模型单价（Dify 模型供应商页面可查）。
- 只调检索侧（Top-K / 阈值 / Rerank / 混合检索）**不需要重建索引**，随时可试——优先从这里下手，零成本。

## ⑤ 建议的体检顺序（低成本→高成本）

1. 开混合检索 + Rerank，Top-K=3，跑召回测试（不动索引，免费）
2. 开 Score 阈值 + 引用归属，人工核对 3 个回答
3. 若分段切断句子/表格 → 改父子分段（需重建该文档索引）
4. 最后才考虑换 Embedding 模型（全量重建，先估成本）
